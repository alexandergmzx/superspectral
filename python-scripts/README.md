# python-scripts

All **Apache-2.0** Python lives here, by convention ([`CLAUDE.md`](../CLAUDE.md#where-python-lives)). Scripts in this tree are referenced from `firmware/`, `dsp/`, `tools/`, `analysis/`, `datasets/` and `tests/`, but never duplicated outside of it.

**The one exception is [`../host/`](../host/)** — the Linux companion and the Praat golden-file generator — which imports parselmouth (GPLv3) in-process and is therefore licensed GPL-3.0-or-later under its own `LICENSE`. The exception exists so the licence boundary is a directory boundary a reviewer can see. The test for where a new script goes is its imports: if it needs parselmouth, librosa-with-GPL-extras, Demucs or any other copyleft dependency, it goes under `host/`; if it is stdlib/NumPy/SciPy-only tooling, it goes here. Never move Apache-2.0 tooling into `host/` for convenience — that relicenses it.

## Current contents

- `check_links.py` — relative-link checker over the tracked `.md`, `.yaml`, `.yml` and `.json`; the local, install-free twin of CI's `lychee --offline` job, and stricter than it in two ways: it reports `path:line` so a failure is clickable, and it validates `#anchors` against the target file's heading slugs under GitHub's rules (including the `-1`/`-2` disambiguation and the double hyphen a dropped em dash leaves behind). A link that resolves to the right file and the wrong section is a defect a path check cannot see. `python3 python-scripts/check_links.py [subtree]`, exit 1 if anything is broken. Skips inline code spans and fenced blocks, which a naive regex misreads as links, and skips targets containing regex metacharacters — `[^0-9.x](19|20)` inside a YAML-embedded regex is Markdown link syntax by accident.
- `check_markers.py` — accounts for every unresolved-value marker in the tree — `(verify`, `(prov.)`, `unread`, `unconfirmed`, and the tagged `TBD (datasheet …)` — against two committed lists: [`markers-closed-2026-08-21.tsv`](../docs/roadmap/markers-closed-2026-08-21.tsv) (corrections that must not come undone) and [`markers-allowlist.tsv`](../docs/roadmap/markers-allowlist.tsv) (`path`, count, **owner**). A marker that is neither fails, so a new one cannot be introduced without naming who owns it, and a correction cannot silently regress. Bare `TBD` is deliberately not scanned — CLAUDE.md sanctions it for a genuinely unmeasured value. It exists because on 2026-08-20 a correction written into ADR 0016 survived in eleven other files for a day, and on 2026-08-21 four items were handed back as "decisions for the owner" when three of them were lookups. `--self-test` checks the matcher against strings that have actually bitten; `--write-allow` re-baselines (review that diff). Wired into the `markers-baseline` pre-commit hook and CI.
- `check_presets.py` — validates every shipped preset in [`../protocols/presets/`](../protocols/presets/) against [`presets.schema.json`](../protocols/specs/presets.schema.json) (draft 2020-12) **and** re-derives loader rules V0–V10 from [`preset-schema.md`](../protocols/specs/preset-schema.md) §6 — canonical form, `id`/filename, watch limits, window coefficients and every `resolution` field to 1×10⁻⁶, `provisional` pointers. Carries its own negative-case suite (41 mutations, each naming the rule that must catch it) and asserts that the owning rule fires even when the schema shadows it, so a rule the C loader will implement is never untested here. `python3 python-scripts/check_presets.py [--verbose]`, exit 1 on any failure. `jsonschema` is optional: without it the rules still run and the schema pass is skipped with a notice. Wired into the `presets-rules` pre-commit hook and the `python-scripts` CI job.
- `gen_colormap_lut.py` — generates the spectrogram colormap LUT for `display_backend` ([ADR 0011](../docs/adr/0011-spectrogram-colormap.md)): 256 RGB565 entries chosen *in* RGB565 (nearest-ΔE representable words under a hard monotone-L\* constraint, solved by DP) rather than by rounding an 8-bit map, with an optional ordered-Bayer dither table and helper. Stdlib only — the colour science (sRGB → CIELAB → CIE76 ΔE) is in the file, so it runs in a bare container. `python3 python-scripts/gen_colormap_lut.py --map cividis --dither -o <header>`; `--self-test` asserts monotone luminance and prints the banding metrics (distinct words, worst ΔE step) and exits non-zero on failure — that is its `tests/` equivalent, which is why it stays a single file past the ~200-line rule below.
- `synth_signals/` — the Tier-0 synthetic generator behind [`../datasets/tier0-synthetic/`](../datasets/tier0-synthetic/) (bibliography [10 P1](../docs/bibliography/10-datasets-and-ground-truth.md)): sines on/off bin centres, full-scale sine and square (the clipping-flag vectors), two-tone at Δf = 0.5/1/2/4 bins, seeded white and FFT-shaped pink noise, linear and exponential (Farina) sweeps, an FM vibrato tone, a Rosenberg-pulse → Klatt-resonator vowel with exact f0 and F1–F3 (plus a vibrato twin), DC + sine, silence — 21 files, 3.0 s, 32 kHz with two 48 kHz host-only twins. Levels follow ADR 0006 D3 (0 dBFS = full-scale sine, `rint(x·32768)` clipped, stated once in `quantise.py`); every file's parameters and derived truths (bin index at N = 4096, clip flag, the square's sampled fundamental, the resonators' poles *and* their |H| peaks) go into the tracked `manifest.yaml` with the sha256 of the WAV bytes. `check` regenerates in memory and fails on any sha256 drift — the reproducibility test; the package docstring records the measured margin against libm differences. First package with runtime dependencies (NumPy, SciPy, PyYAML), so it is its own uv project: `cd synth_signals && uv sync --frozen --extra test && uv run pytest -q` (21 hazard-named tests) and `uv run python -m synth_signals generate|check --out ../../datasets/tier0-synthetic`. Run with the ROS 2 `PYTHONPATH` stripped, as `.envrc` does.
- `golden_compare/` — the Apache-2.0 consumer of the golden files: reads the `manifest.yaml` and `.npy` arrays that [`../host/golden/`](../host/golden/) (GPL) wrote **as data, never as an import** (no `spectral_host`, no `sys.path`; a test greps the package for both) and applies the tolerance table of [`golden-files.md`](../docs/validation/golden-files.md) to a candidate — a device dump, a `host-tests` result, an esp-dsp backend. `load.py` trusts an array only after `allow_pickle=False`, sha256, dtype and shape agree with its `outputs[]` entry and the manifest says `schema: "1.1"` (one value accepted, the integer `1` refused); `spectrum.py` takes the per-bin dB residual with the golden's bins below the floor masked — the mask never widens the atol, and nothing compared is not a pass; `pitch.py` is the frame-grid trap made code: `resample_to_times` puts the Praat track on the device's frame times (linear in log f, voiced runs only, never across a gap) before `median_abs_cents`, and `mir_eval_melody` returns RPA/RCA/OA/VR/VFA — the pitch verdict is the median row **and** the voicing row (VR ≥ 90 %, VFA ≤ 10 %), so an estimator that is exact on the few frames it voices does not pass; `windows.py` is the device lane's hasher for the **exact** digest row — the C side dumps a window table as raw little-endian float32 and carries no sha256, this hashes it and says how far a miss is (`max |Δ|` against the entry's own coefficients, the `atol = 1e-6` row). `tolerances.py` copies the table's constants, each bound to the row it came from, and `tests/test_tolerances_match_golden_files_md.py` greps the document in both directions so it stays the only definition. Own uv project (NumPy, PyYAML, `mir_eval`): `cd golden_compare && uv sync --frozen --extra test && uv run pytest -q` (111 hazard-named tests; the tier-0 golden set is read when on disk) and `uv run python -m golden_compare spectrum|pitch|window|tolerances …` — exit 0 pass, 1 fail, 2 a file that did not match its manifest. Run with the ROS 2 `PYTHONPATH` stripped, as `.envrc` does.
- `doc_ocr/` — turns the PDFs under `docs/` into grep-able markdown sidecars carrying a human review flag, and maintains the tracked ledger [`../docs/OCR/manifest.tsv`](../docs/OCR/manifest.tsv). Stdlib only (shells out to poppler / mutool / ocrmypdf); run as `python3 -m doc_ocr` from `doc_ocr/`. Carried over from the author's `swarm` repository with only `Settings.skip_dirs` adjusted. See [`../docs/OCR/README.md`](../docs/OCR/README.md). Tests: `cd doc_ocr && python3 -m pytest -q` (25 tests, no binary fixtures, no poppler needed) — run in CI.

## Adding a script

1. Pick a `snake_case` name that says what it does (`pack_wav_as_take.py`, not `script1.py`).
2. SPDX header on line 1–2 (`# SPDX-FileCopyrightText: 2026 Alexander Gomez` / `# SPDX-License-Identifier: Apache-2.0`), then a top-of-file docstring with its CLI (one usage example minimum).
3. If it grows beyond ~200 lines or accretes dependencies, move it to a `<package>/` subfolder with a `pyproject.toml` and a `tests/` directory whose test names state the hazard they guard (see `doc_ocr/tests/`).
4. Tools invoked from the bench or the shell get a thin entry point under [`../tools/`](../tools/) that calls the script by relative path.

## Environment

Scripts target the system Python 3.12 (`/usr/bin/python3`) and depend only on the standard library until a package justifies more; CI runs `python -m compileall -q python-scripts` on every push, which is why `doc_ocr` takes no runtime dependencies. A package that needs NumPy/SciPy/`mir_eval` gets its own pinned `pyproject.toml`, `uv.lock` and `.python-version` (`synth_signals/` and `golden_compare/` are the first two) and its own `.venv` under the package directory — separate from the ESP-IDF Python environment (the IDF venv under `~/esp/tools/v6.0.2` is never used for repo scripts) and separate from `host/`'s GPL environment. The three never mix.

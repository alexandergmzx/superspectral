# 0013 — The native-Linux simulator is a first-class target: `spectral_core` and `ui` build on the host, so the golden-file harness and the UI design loop never wait for the watch

- **Status:** accepted
- **Date:** 2026-08-21
- **Context:** There is one sealed watch, and reaching it is expensive. Every on-device iteration is a `tools/flash.sh` write to `ota_1`, a 3 s boot guard, a rollback window and a mark-valid decision ([ADR 0015](0015-anti-brick-policy.md), [experiment 0002](../validation/experiments/0002-rollback-and-boot-guard-race.md)); the whole-flash read of 2026-08-20 ran at **≈ 10 KB/s over USB-Serial-JTAG** ([`docs/hw/README.md`](../hw/README.md)), which is the honest order of magnitude for that lane. Unattended sessions may not touch the watch at all. Meanwhile the two things that need the most iterations need no watch in principle: the **golden-file harness** compares on-device DSP against Praat/parselmouth vectors that are *files* ([`golden-files.md`](../validation/golden-files.md), [ADR 0009](0009-golden-file-strategy.md)), and the **UI design loop** on a 240×240 canvas needs a window, not a wrist. QEMU sits in between — it runs the real Xtensa binary, the real dual-core FreeRTOS, real octal PSRAM, eFuses and GPIO straps, but emulates **no I²S, I²C, GP-SPI or USB** ([07 #17](../bibliography/07-technical-reports.md), [11 A33](../bibliography/11-esp-idf-platform-and-toolchain.md)), so it sees neither the microphone, the panel, nor the console. The idea of building the same watch UI natively on Linux is taken outright from **sharandac/My-TTGO-Watch** ([06 #41](../bibliography/06-reference-projects.md)) — GPL-2.0, therefore **idea only, no code** ([ADR 0004](0004-split-licensing.md)).
- **Decision:** Three lanes, named, with the seams that make them possible written into the component contracts.

  | Lane | Built with | `audio_source` | `display_backend` | Proves | Cannot prove |
  |---|---|---|---|---|---|
  | **host (native Linux)** | plain CMake, host compiler, ASan/UBSan — no ESP-IDF, no `.envrc` | `file_blob` · `synthetic` | `sdl` | DSP numerics vs golden vectors; widget layout, colormap, text, state machines | anything with a clock, a bus or a rail |
  | **QEMU (`esp32s3`)** | `sdkconfig.ci.qemu`, `idf.py qemu` | `file_blob` · `synthetic` | `qemu_rgb` ([06 #16](../bibliography/06-reference-projects.md)) | real instructions incl. esp-dsp `_aes3`, SMP scheduling, PSRAM/MMU, partition table, boot + rollback | mic, panel SPI, touch, USB console, timing that depends on any of them |
  | **hardware** | `tools/flash.sh` → `ota_1` | `pdm_mic` (+ the others) | `st7789_spi` | every number in the research question | — |

  1. **Two host executables, both Apache-2.0, both plain CMake, both outside the GPL [`host/`](../../host/golden/README.md) tree.** [`host-tests/`](../../host-tests/README.md) already builds [`spectral_core`](../../firmware/twatch-s3/components/spectral_core/README.md) (pure C99, `REQUIRES ""`) under sanitizers with ctest. A second target, `host-sim`, links `spectral_core` + [`ui`](../../firmware/twatch-s3/components/ui/README.md) + LVGL 9.5.0 with `LV_USE_SDL=1`, opening a 240×240 window through `lv_sdl_window_create(240, 240)` and standing in for the FT6336U with `lv_sdl_mouse_create()`. It lands with the first `ui` source file, not before.
  2. **The seams are normative.** [`audio_source`](../../firmware/twatch-s3/components/audio_source/README.md): `pdm_mic` | `file_blob` | `synthetic`. [`display_backend`](../../firmware/twatch-s3/components/display_backend/README.md): `st7789_spi` | `qemu_rgb` | **`sdl`** — the third back end is added by this ADR. The invariants that keep them real: `spectral_core` contains zero `esp_*` includes; `ui` receives a `spectral_frame_t` and a display handle and touches no register; everything that touches a register lives in `twatch_bsp` and is therefore hardware-only by construction.
  3. **One `lv_conf.h`**, committed under `firmware/twatch-s3/` and included by both builds. Only driver switches differ (`LV_USE_SDL` on the host; `LV_USE_TEST` + `LV_USE_TEST_SCREENSHOT_COMPARE` in the screenshot build). Colour depth, fonts and widget set must match or the screenshots are lying about the watch.
  4. **Screenshot regression calls the LVGL function directly, never LVGL's Unity macro.** Verified in the pinned LVGL 9.5.0 tree on 2026-08-21: `lv_test_screenshot_compare(const char *fn_ref)` lives in `src/debugging/test/lv_test_screenshot_compare.c`, is gated by `LV_USE_TEST` + `LV_USE_TEST_SCREENSHOT_COMPARE` (needs lodepng and a few MB), converts the **active display buffer — `LV_COLOR_FORMAT_RGB565` and `RGB565_SWAPPED` included** — to XRGB8888 and compares per channel with a tolerance. LVGL's own `TEST_ASSERT_EQUAL_SCREENSHOT` in `tests/unity/unity_support.h` `TEST_IGNORE`s unless `LV_COLOR_DEPTH == 32` **and** the display is 800×480, so on a 240×240 RGB565 screen it would silently skip every assertion. Two further traps we own: `LV_TEST_SCREENSHOT_CREATE_REFERENCE_IMAGE` defaults to `1`, which makes a **missing** reference image *pass* (set it to `0` in CI, `1` only when deliberately regenerating), and the compare reads a full-screen active buffer, whereas the watch renders through two ~1/8-screen partial buffers ([02 #25](../bibliography/02-application-notes.md)) — the simulator's render mode is deliberately not the watch's. This supersedes the sentence in [`ui/README.md`](../../firmware/twatch-s3/components/ui/README.md) that says the widget set runs in LVGL's native screenshot harness unchanged.
  5. **QEMU is the middle lane, not a substitute.** It owns what only real instructions can settle — the esp-dsp-vs-reference **backend-agreement** test ([ADR 0009](0009-golden-file-strategy.md), [`golden-files.md`](../validation/golden-files.md)) and boot/partition/rollback smoke — and nothing that needs I²S, I²C, GP-SPI or USB (hence the UART console overlay in [`sdkconfig.ci.qemu`](../../firmware/twatch-s3/sdkconfig.ci.qemu); [pitfalls G6–G9](../devenv/pitfalls.md)). The QEMU on this host is `esp_develop_9.0.0_20240606` and must be replaced by `idf_tools.py install qemu-xtensa` in the pinned tools root before the lane is used ([pitfall A22](../devenv/pitfalls.md), [setup.md](../devenv/setup.md)).
  6. **Provenance is auditable.** From My-TTGO-Watch we take one sentence — *build the same watch UI natively on Linux for testing* — and nothing else. No file, no snippet, no `lv_conf.h`, no CMake from that project enters this tree; the simulator is written against LVGL's own SDL driver (MIT, [06 #12](../bibliography/06-reference-projects.md)). The catalogue row stays graded **read-only** ([06 #41](../bibliography/06-reference-projects.md), [`docs/reference-projects/`](../reference-projects/README.md)).
  7. **What the simulator may never be.** It is not an oracle for latency, refresh rate, DMA, SPI timing, `MADCTL`/gap behaviour, FPU scheduling or power. Every research-question number (±20 cents, ≥ 30/50 Hz, ≤ 80 ms, ≥ 3 h) is measured on hardware, on both measurement paths, exactly as before: **this ADR adds no validation row**, deliberately, because a lane that cannot carry a metric must not appear to.
- **Alternatives:**
  - *ESP-IDF's `linux` target (host apps) as the host lane.* Rejected as primary: esp-dsp registers its Xtensa `.S` files unconditionally and its ANSI-C sources include `esp_attr.h`/`esp_log.h` ([pitfall G2](../devenv/pitfalls.md)), and the POSIX FreeRTOS simulator is cooperative — *"a context switch happens only when a task interacts with the FreeRTOS kernel"* ([11 A36](../bibliography/11-esp-idf-platform-and-toolchain.md), [02 #44](../bibliography/02-application-notes.md)) — so a green concurrency test there means nothing. Kept as an optional second lane for pure math and CMock. **Trigger:** esp-dsp declaring `linux` in its `targets:`.
  - *QEMU only, no native lane.* Rejected: no sanitizers on the code under test, no window to look at, minutes per iteration instead of seconds, and it does not run until a fresh `qemu-xtensa` is installed.
  - *Wokwi as the UI simulator.* Rejected beyond advisory ([06 #58](../bibliography/06-reference-projects.md), [02 #51](../bibliography/02-application-notes.md)): hosted, token-gated on forks, with an official "results may differ from real hardware" caveat. Its one real advantage — an actual SPI transaction against an ST7789 model — belongs to the display-driver question ([ADR 0007](README.md)), not to UI design. **Trigger:** the scroll-axis check needing a pre-hardware rehearsal.
  - *Vendor My-TTGO-Watch's simulator scaffolding.* Rejected permanently: GPL-2.0 code in an Apache-2.0 firmware tree ([ADR 0004](0004-split-licensing.md)). Not revisitable.
  - *A separate simulator project with its own copy of the widgets.* Rejected: a second copy of the UI diverges within a week; the seams exist precisely so one source serves three lanes.
  - *LVGL's X11, Wayland or `fbdev` drivers instead of SDL.* Deferred, not rejected — 9.5 ships all of them. SDL wins because one driver also provides mouse, keyboard and mousewheel (the crown surrogate). **Trigger:** a headless CI runner where SDL's window is a problem → `LV_USE_LINUX_FBDEV` on a dummy framebuffer.
  - *No simulator; iterate on hardware.* Rejected: nights when the watch may not be touched are normal here, and the sealed-board recovery discipline makes every flash a small ceremony.
- **Consequences:**
  - (+) The UI design loop and the golden-file harness run on any Linux box with no watch, no `.envrc` and no QEMU — seconds per iteration, with ASan/UBSan over exactly the source the watch executes.
  - (+) The seams pay for themselves three times over: `file_blob` is also the digital-injection validation path (proposal §4), `synthetic` is also the Tier-0 corpus driver ([`datasets/`](../../datasets/README.md)), `qemu_rgb` is also the CI display.
  - (−) A third `display_backend` and a second host build to keep green. Every UI feature must be written against a panel handle and a frame struct; the day someone reaches for a `twatch_bsp` symbol from `ui`, the simulator stops compiling. That break is the mechanism, but it is friction.
  - (−) The simulator is honest about pixels and lies about everything else. A green simulator with a red watch is a normal outcome, and no frame rate measured in it may ever be quoted.
  - (−) `lv_conf.h` skew is a silent failure: two configurations, one screenshot set, no error. Mitigated by a single committed file rather than by review.
  - (−) LVGL's own screenshot macro is unusable at 240×240 RGB565, so we own the wrapper — including the default that lets a missing reference image pass.
  - (−) SDL2 development headers become a host and CI prerequisite; the `espressif/idf` container does not carry them, so the simulator job runs in a plain container, not the IDF one.
  - (−) `twatch_bsp` — AXP2101 rail order, I²C bus ownership, the ST7789 init sequence, the PDM `slot_mask` — is testable in **no** lane but hardware. The richest source of bring-up bugs has no simulator, and this ADR does not change that.

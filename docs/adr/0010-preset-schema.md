# 0010 — The preset is the contract: every preset states its own analysis bandwidth, window constants and mic-EQ slot, and is addressed by the sha256 of its canonical form

- **Status:** accepted
- **Date:** 2026-08-21
- **Context:** The six presets are the product's user model — the founding research document ([`00-linux-analyzer-architecture-and-build-guide.md`](../research/00-linux-analyzer-architecture-and-build-guide.md) §B) defines them as JSON with `fft_size`, `window`, `interval_ms`, `smoothing`, `decimations`, `overlays` and `freq_scale`, and CLAUDE.md carries them forward to the watch. That definition is not sufficient here, for three separate reasons.
  1. **It has no bandwidth.** A preset that says "8192-point Hann" has not said what its spectrogram *shows*. The classical sound spectrograph's pair is 300 Hz wideband / 45 Hz narrowband (Koenig, Dunn & Lacy 1946); Praat's Gaussian convention gives 260 Hz at 5 ms and 43 Hz at 30 ms. Neither is a property of an FFT size. As long as the presets name only a size and a window, **"wideband" and "narrowband" are undefined in this design** — the completeness critique's spectrogram-bandwidth point — and so is the dB axis: a tone must be divided by the window's coherent gain and a noise power by its ENBW, and getting that backwards is the classic "my noise floor is 2 dB off" bug ([05](../bibliography/05-papers.md) #1, #2).
  2. **It has no microphone slot.** [ADR 0003](0003-microphone-path.md) decision 7 permits exactly four operations in the analysis path — DC removal, a minimum-phase mic EQ, windowing, and a fixed logged gain — and names "ADR 0010's mic-EQ slot" as where the EQ lives. There is no such slot yet, and there is no EQ yet either: validation [experiment 0001](../validation/experiments/0001-pdm-mic-in-situ-characterization.md) fits the first one.
  3. **It has no identity.** `TAKE_HEADER` is specified to carry "preset id + sha256 of the preset JSON" ([`protocols/README.md`](../../protocols/README.md)), which requires a byte-exact definition of what gets hashed. Without one, a whitespace change silently orphans every take recorded before it.

  On top of that, the founding definition was written for a browser plus a Python backend at 48 kHz. The watch is a different machine: 32 kHz by default with 48 kHz gated on a measurement ([ADR 0003](0003-microphone-path.md) decision 5), a ≈ 112–144 KB `(prov.)` internal-SRAM working set at N = 8192 and 224 KB as the hard ceiling, a 50 Hz analyzer-canvas ceiling, and one preset (`stem_analysis`, Demucs + DTW) that cannot run on it at all. A schema that can express a preset the hardware cannot run is a schema that lets a user brick their own measurement.
- **Decision:** The preset JSON schema is owned by [`protocols/specs/`](../../protocols/specs/README.md), versioned, and enforced. Three artefacts: the prose spec [`preset-schema.md`](../../protocols/specs/preset-schema.md), the machine-readable [`presets.schema.json`](../../protocols/specs/presets.schema.json) (JSON Schema **draft 2020-12**), and the six instances in [`protocols/presets/`](../../protocols/presets/).

  1. **Six blocks, `additionalProperties: false` at every level.**

     ```
     preset.json
     ├── schema_version  id  name  description  targets[]        identity + routing
     ├── analysis                                                 what the watch computes
     │   ├── sample_rate_hz  fft_size  interval_ms  decimations
     │   ├── window     { name, form, coefficients,               the window itself
     │   │               coherent_gain, coherent_gain_db, enbw_bins }
     │   ├── resolution { bin_width_hz, window_duration_ms,       what (window, N, f_s) buys
     │   │               enbw_hz, hop_samples }
     │   └── spectrum_type  db_reference  weighting  dc_blocker_hz
     │       averaging  averaging_frames  smoothing  hold
     ├── mic_eq   { mode: none | ref | inline, … }                ADR 0003 decision 7
     ├── display  { freq_scale, freq_min/max_hz, db_floor/ceiling,
     │              refresh_hz_target, colormap_id?, overlays[] }
     ├── host     { reference, separation, align }                host-target presets only
     ├── guidance                                                 the per-preset environment note
     └── provisional[]   JSON Pointers to fields still `(prov.)`
     ```

  2. **`enbw_hz` and `coherent_gain` are mandatory, and the words are banned.** Every preset carries the window's cosine-sum coefficients exactly as esp-dsp commits them, its coherent gain (*a*₀) and its NENBW in bins, plus the derived `enbw_hz = enbw_bins × f_s / N`. **"Wideband" and "narrowband" do not appear in a preset file**; the UI prints `enbw_hz` and `window_duration_ms` and the spec tabulates the two published conventions so a reader can place the number. The redundancy is checked, not trusted: a loader recomputes all three from `coefficients` and rejects on a disagreement above 1×10⁻⁶ (rule V8).
  3. **`targets: ["watch"|"host"]` is the hardware envelope, not documentation.** A preset that names `watch` is constrained by the schema to `fft_size ≤ 8192`, must carry `refresh_hz_target ≤ 50`, and may not list a host-only overlay (`stem_f0`, `dtw_path`); the loader additionally rejects `sample_rate_hz: 48000` until experiment 0001 clause 4 opens that gate. `stem_analysis` is `["host"]` and is stored on the watch but never offered by it. A **host-only** preset may name 48 kHz today — the gate is on the capture path, and the host reads files, not microphones.
  4. **Analysis rate and display rate are separate fields.** `interval_ms` is the hop; `display.refresh_hz_target` is frames pushed to the panel. `1000 / interval_ms` must be an integer multiple of `refresh_hz_target` (rule V7), i.e. a whole number of spectrogram columns per rendered frame — which is how `diction_consonants` computes at 100 frames/s and renders at 50 Hz, two columns per frame, on a canvas the ST7789 scrolls in hardware.
  5. **`mic_eq` is one of exactly three shapes:** `{"mode":"none"}`; `{"mode":"ref", "eq_id", "sha256"}` pointing at `eq/<eq_id>.json` on the same partition; or `{"mode":"inline", "eq_id", "design_sample_rate_hz", "scope", "biquads"}` with ≤ 8 RBJ-convention sections in esp-dsp's `dsps_biquad_f32` coefficient order. `scope` records whether the curve is a per-part-number constant or a per-unit calibration — the schema stores that answer, it does not choose it. All six shipped presets are `none`, because no EQ has been fitted.
  6. **Identity is the sha256 of the file's bytes, and the file's bytes are the canonical form** (UTF-8, LF, one trailing newline, keys sorted by code point, two-space indent, decimal numbers with at most 6 decimal places — the schema's ranges keep every value inside the region where Python, ECMAScript and C agree on the shortest round-trip decimal, so no canonicalisation library is needed on either side). Nothing on the watch re-serialises JSON to check a hash.

     ```
     preset file bytes ──sha256──► preset_sha256 ──┐
     eq/<eq_id>.json  ──sha256──► eq_sha256 ──┐    │
                                              ▼    ▼
     firmware ──esp_app_desc──► app_elf_sha256 ──► TAKE_HEADER (kind 0x01)
     ```

  7. **The watch validates and rejects; it never coerces.** No clamping, no substituted defaults, no silently dropped unknown field. A preset that fails any of rules V0–V10 is not loaded, the previous preset stays active, and the rule number is logged. `schema_version` is `MAJOR.MINOR.PATCH`; a loader accepts MAJOR 1 and refuses everything else.
  8. **Storage is the LittleFS `presets` partition** — 1 MB at `0x821000`, subtype `0x83`, wear-levelled and power-fail safe, which is the reason [ADR 0014](0014-partition-layout-frozen.md) rejected SPIFFS for it. `presets/<id>.json`, `eq/<eq_id>.json`, and an `index.json` (id → file, sha256, bytes, schema_version) written by the host and only read by the watch. The whole shipped set is 9,323 bytes.
  9. **Changing the schema is an ADR and a coordinated commit** across firmware, host, validation and the instances — the same rule the take format lives under. MINOR adds optional fields; MAJOR is a rewrite of every instance.
- **Alternatives:**
  - *Keep the founding document's field set and add nothing.* Rejected: it cannot express a bandwidth, a mic EQ, a target or an identity, and three other documents already forward-reference all four. Reopen trigger: none — the forward references are the requirement.
  - *Compute `resolution` and the window constants at load time instead of storing them.* Rejected: a take manifest that names `enbw_hz` is self-describing five years later; one that names `"window": "hann"` needs the reader to own the same table the writer owned, which is precisely the coupling that produces silent dB-axis disagreements. Reopen trigger: if `TAKE_HEADER` ever grows explicit bandwidth and gain fields of its own, the preset's copy becomes redundant and can drop to optional.
  - *Hash a canonical re-serialisation (RFC 8785 JCS) rather than the file bytes.* Rejected for v1: it puts an ECMAScript-compatible float formatter on a microcontroller to solve a problem the schema's value ranges already prevent. Reopen trigger: a host-side editor that reformats files it did not write, or a schema field whose range admits exponent notation.
  - *Binary preset records with a `_Static_assert`, like the take format.* Rejected: presets are the one artefact a human edits and diffs, and `CLAUDE.md` already draws the line there ("binary on flash — presets are JSON because the host edits them"). Reopen trigger: if preset parsing ever shows up as a boot-time or memory problem measured on target, not assumed.
  - *One `presets.json` array instead of one file per preset.* Rejected: per-preset hashing, per-preset atomic replacement and per-preset corruption containment all follow from one file per preset, and LittleFS makes small files cheap.
  - *YAML or TOML.* Rejected: no draft-2020-12-class validator on either side, and YAML's implicit typing (the Norway problem) is exactly the silent coercion decision 7 forbids.
  - *An `enum` for `colormap_id` now.* Deferred, not rejected: [ADR 0011](README.md) chooses the map and the RGB565 LUT. Until then the field is an open string and no shipped preset sets it. Reopen trigger: ADR 0011 accepted.
  - *Carry the ring/twang band edges in the preset.* Rejected: the edges are unsettled in the literature (2.5–3.5 kHz vs Omori's 2–4 kHz vs Bloothooft & Plomp's 1/3-octave bands) and belong to [ADR 0008](README.md). `overlays` names which readout is drawn, never where its edges are.
- **Consequences:**
  - (+) A take is reconstructible from its header alone: preset sha256 + `app_elf_sha256` + the mic-EQ id pin the entire analysis that produced it, and the window constants needed to interpret its dB axis travel inside the preset.
  - (+) The schema cannot express a preset the watch cannot run — the SRAM ceiling, the display ceiling, the 48 kHz gate and the host-only overlays are all `if/then` clauses, verified by negative tests rather than by a comment.
  - (+) Making the bandwidth explicit immediately paid for itself: **all six presets turn out to be narrowband analyses**, and `diction_consonants` — the transient preset, where the classical tool is a *wideband* window — has an ENBW of 46.875 Hz, essentially Koenig's 45 Hz **narrowband** figure rather than his 300 Hz wideband one. The schema surfaces it; it does not fix it.
  - (−) …and it does not fix it. Until ADR 0006 or a preset-content ADR acts, the consonant preset is analysed with a window about 6× too narrow for the job it is named after. This ADR deliberately stops at making the number visible.
  - (−) Derived data is stored. `resolution` and the two window constants duplicate what `coefficients`, `fft_size`, `sample_rate_hz` and `interval_ms` already determine; rules V8/V9 keep them honest, but a hand-edited preset that changes N without recomputing `resolution` **fails to load** rather than quietly working. That is the intended behaviour and it will still surprise someone.
  - (−) `additionalProperties: false` plus reject-don't-coerce means MINOR versions are additive only *forwards*. Older firmware refuses a preset carrying an optional field it has never heard of. Mitigation: the host writes the lowest `schema_version` that expresses the preset, and `index.json` carries a per-file `schema_version` so the watch skips what it cannot load instead of failing to mount — but preset files and firmware versions are coupled more tightly than "MINOR is additive" suggests.
  - (−) A JSON parser, a sha256 and a validator now sit in the watch's start-up path for six files that could have been a C array. The code and RAM cost is **TBD** until the loader exists, and it competes for the same internal SRAM the FFT buffers need.
  - (−) `48000` sits in the `sample_rate_hz` enum as reserved-and-rejected. An enum value the loader refuses is a wart, and if experiment 0001 clause 4 fails it has to be removed in a MAJOR bump that rewrites every instance's `schema_version`.
  - (−) `mic_eq` is `none` in all six presets, so every band-energy readout is uncorrected today: the slot exists, the correction does not. The mic's HF rise sits inside the twang band, so this is a real bias, not a formality — which is why the validation plan reports uncorrected and post-EQ values separately.
  - (−) Two display numbers are datasheet-derived rather than measured — `db_floor_dbfs` (from the 61.5 dB(A) SNR plus the FFT processing gain) and the 12.8 kHz `freq_max_hz` cap (0.4·f_s, because the S3's PDM→PCM decimation-filter response is undocumented above it). Both are listed in each preset's `provisional` array, but a user still sees an axis whose ends are expectations.
  - (−) Spectroid's own enumerated values are still an unretrieved primary source ([07](../bibliography/07-technical-reports.md) #9 is a manual capture task nobody has done). The enums here are reconstructed from the founding document, so a setting Spectroid offers and this schema forbids will only be discovered when that capture happens.
  - Flagged as a validation item: schema validation of `protocols/presets/*.json` and the V0–V10 recomputation are a CI gate ([`python-scripts/check_presets.py`](../../python-scripts/check_presets.py) — written 2026-08-21, in the `python-scripts` CI job and the `presets-rules` pre-commit hook; 6/6 presets accepted, 41/41 negative cases rejected) and, **still to be written**, a `spectral_core` host test, because the C loader must reject exactly the files the Python validator rejects; the `refresh_hz_target` of every watch preset is checked by the *Sustained refresh* and *Dropped-frame rate* rows of [`../validation/README.md`](../validation/README.md) with the phototransistor cross-check, not the firmware counter alone; `db_floor_dbfs` and `freq_max_hz` are re-set from [experiment 0001](../validation/experiments/0001-pdm-mic-in-situ-characterization.md).

  Verified when this record was written: all six presets validate against `presets.schema.json` under `jsonschema` 4.10.3 `Draft202012Validator` (6/6), the V0–V10 arithmetic rules recompute to within 1×10⁻⁶, and a 30-case negative suite is rejected as designed — 21 of the 30 by the schema alone, the other 9 (a mutated coefficient set, an inconsistent `enbw_bins`/`enbw_hz`/`hop_samples`, a hop that yields fractional spectrogram columns per frame, an `id` that does not match its filename, an unresolvable `provisional` pointer, a `freq_max_hz` above Nyquist, an inline mic EQ designed at another rate) only by the loader rules — with 4 positive controls accepted.

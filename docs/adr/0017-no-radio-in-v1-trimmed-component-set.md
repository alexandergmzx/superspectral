# 0017 — No radio in v1: the build contains only `main` and what it requires (no Wi-Fi, BT, lwIP, OpenThread)

- **Status:** accepted
- **Date:** 2026-08-21
- **Context:** Super Spectral v1 is a wrist-worn *live* analyzer; takes reach the host over USB ([ADR 0002](0002-companion-architecture.md), [`protocols/specs/`](../../protocols/specs/README.md)). No radio is used — the SX1262 stays in reset with ALDO4 off. Yet the first firmware builds linked **every** component in the ESP-IDF tree (`bt`, `esp_wifi`, `esp_netif`, `lwip`, `openthread`, `esp_https_ota`, `wpa_supplicant`, …): ESP-IDF's default `COMPONENTS` is "everything", and only the linker prunes. Three concrete costs showed up on 2026-08-21: (1) the promptless `CONFIG_ESP_WIFI_ENABLED` (`bool` / `default y if SOC_WIFI_SUPPORTED`, `components/esp_wifi/Kconfig`) could not be turned off from `sdkconfig.defaults` — the generated sdkconfig read `=y` whatever the file said (pitfall H11); (2) the very first CI run of the analyzer configuration failed on a `-Wanalyzer-null-dereference` inside **lwIP** (`tcp_out.c`), code this product never executes; (3) the Wi-Fi/BT stacks pin high-priority tasks to core 0 and reserve DMA-capable internal RAM — the scarce resource the PDM→FFT→display pipeline competes for ([`docs/architecture/`](../architecture/README.md) tenets).
- **Decision:** Make the radio exclusion **structural, not a Kconfig wish.**
  - `firmware/twatch-s3/CMakeLists.txt` sets **`set(COMPONENTS main)`** before `project()`. The build contains `main`, the six project components, the registry components from `main/idf_component.yml`, and the IDF components they transitively `REQUIRES` — nothing else. Verified 2026-08-21: `bt`, `esp_wifi`, `esp_netif`, `lwip`, `openthread`, `esp_https_ota`, `esp_http_*`, `wpa_supplicant`, `esp_coex`, `esp_phy` are gone from `build/esp-idf/`; `CONFIG_ESP_WIFI_ENABLED` no longer exists in `sdkconfig`; the app shrank from 0x2be90 to 0x267e0 bytes.
  - The pre-commit hook `sdkconfig-invariants` asserts the `set(COMPONENTS main)` line (replacing the earlier, ineffective grep for `CONFIG_ESP_WIFI_ENABLED=n`). `CONFIG_BT_ENABLED=n` stays in `sdkconfig.defaults` as a declaration of intent; with `bt` out of the component set the symbol does not exist and the line is ignored.
  - The `phy_init` partition (4 KB) is **retained** in [`partitions.csv`](../../firmware/twatch-s3/partitions.csv) so a future radio does not require re-freezing offsets ([ADR 0014](0014-partition-layout-frozen.md)).
  - The GCC static analyzer (`sdkconfig.ci.analyzer`) is **blocking** again in CI: with the trimmed set it runs clean over project and IDF code. Registry components are excluded (`-fno-analyzer` appended per target in the top-level CMakeLists — `esp_lvgl_port` needs an explicit line because it compiles through a separately named `lvgl_port_lib`), because their findings (esp-dsp 1.8.2: `va_start` without `va_end` in `aes3_tie_log.c`, unchecked `malloc` in `dsps_*_init`; esp_lvgl_port 2.9.0: a leak and an uninitialised read on an error path) are real but not ours to fix; they are reported upstream.
- **Alternatives:**
  - *`CONFIG_ESP_WIFI_ENABLED=n` / `CONFIG_BT_ENABLED=n` in `sdkconfig.defaults` only.* Rejected: the Wi-Fi symbol is promptless and ignored; BT=n removes the stack but leaves the components, the Kconfig surface and the analyzer noise in place. It was the state of the tree until this ADR and it did not work.
  - *`EXCLUDE_COMPONENTS` list.* Rejected: a denylist rots every time IDF adds a component; the allowlist (`COMPONENTS main`) is the form Espressif's build-system guide recommends for production projects and it is self-maintaining through `REQUIRES`.
  - *Keep the analyzer advisory instead of scoping it.* Rejected: an advisory analyzer is one nobody reads. Scoping it to code we can fix keeps it blocking.
  - *Add a radio now (BLE companion link).* Deferred, not rejected: if v2 adds BLE for a phone companion, this ADR is superseded and coexistence must be re-benchmarked against the audio-dropout metric ([validation](../validation/README.md)) before any audio task shares core 0 with the controller.
- **Consequences:**
  - (+) Smaller, faster builds; the Kconfig surface matches the product; no promptless-symbol surprises; the analyzer gates the merge.
  - (+) The host link is forced to be USB, which is also the only recovery path — one cable, one story ([ADR 0015](0015-anti-brick-policy.md)).
  - (−) Any new `#include` of an IDF component not yet in the dependency graph fails with "component X is not in the requirements list" until it is added to a `REQUIRES` — deliberate friction, documented in [`firmware/twatch-s3/README.md`](../../firmware/twatch-s3/README.md).
  - (−) Registry components are not analyzed by `-fanalyzer`; their quality is what their maintainers ship. The upstream reports are the mitigation.
  - (−) Adding a radio later is an ADR-level change (this one is superseded), not a Kconfig flip.

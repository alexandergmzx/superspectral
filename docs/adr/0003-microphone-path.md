# 0003 — The microphone path is fixed by silicon: PDM RX on I2S0, 16-bit slots, 32 kHz default, and every conditioning step linear and in software

- **Status:** accepted (the 48 kHz clause is a measurement item — see *Flagged as a validation item* below)
- **Date:** 2026-08-21
- **Context:** The T-Watch S3 carries **one** Knowles SPM1423HM4H-B PDM MEMS microphone (CLK GPIO44, DATA GPIO47) and one MAX98357A I²S amplifier (BCLK GPIO48, WS GPIO15, DIN GPIO46) — [`docs/hw/twatch-s3-pins.md`](../hw/twatch-s3-pins.md). Every number the research question promises (f0 in cents, EIN, AOP, band ratios, latency) is measured through that one mic, so the capture path is not a place for convenience: proposal §3 tenet 2 says "the microphone decides everything". Three constraints are not ours to choose. (1) In ESP-IDF v6.0.2 PDM RX exists only on I2S0: `esp_driver_i2s/i2s_pdm.c` guards both `i2s_channel_init_pdm_rx_mode()` and `i2s_channel_reconfig_pdm_rx_slot()` with `ESP_RETURN_ON_FALSE(handle->controller->id == I2S_NUM_0, …, "This channel handle is registered on I2S1, but PDM is only supported on I2S0")`, and `i2s_pdm_rx_set_clock()` additionally rejects `I2S_CLK_SRC_EXTERNAL`. (2) `i2s_pdm_rx_slot_config_t` documents both `data_bit_width` and `slot_bit_width` as *"only support 16 bits for PDM mode"*. (3) The ESP32-S3 has **no hardware PDM high-pass**: `SOC_I2S_SUPPORTS_PDM_RX_HP_FILTER` is not defined in `components/soc/esp32s3/include/soc/soc_caps.h` at the pinned tag (only the P4 defines it), so `hp_en`, `hp_cut_off_freq_hz` and `amplify_num` do not even exist in the slot struct on this target. That the driver and its API are present, buildable and linkable at the pin is gate evidence, not a documentation claim: gate stage 1 compiled `esp-idf/esp_driver_i2s/…/i2s_pdm.c.obj` with zero warnings and `gate_main.c` takes the address of `i2s_channel_init_pdm_rx_mode` (link-checked) — [`firmware/idf-gate/`](../../firmware/idf-gate/README.md), 2026-08-20 on ESP-IDF v6.0.2. What is *not* settled: which AXP2101 rail powers the mic, and whether the mic tolerates the 48 kHz clock.
- **Decision:**
  1. **Capture on I2S0, PDM RX, master, RX-only handle.** `i2s_new_channel()` with `I2S_CHANNEL_DEFAULT_CONFIG(I2S_NUM_0, I2S_ROLE_MASTER)` and a NULL TX handle, then `i2s_channel_init_pdm_rx_mode()` with CLK = GPIO44, DIN = GPIO47, `clk_inv = false`. Not a preference — the driver rejects anything else. Runtime confirmation on the pinned tree (an I2S1 handle must return `ESP_ERR_INVALID_ARG`) is roadmap item **E2 H6**.
  2. **16-bit slots, PCM data format, mono.** `I2S_PDM_RX_SLOT_PCM_FMT_DEFAULT_CONFIG(I2S_DATA_BIT_WIDTH_16BIT, I2S_SLOT_MODE_MONO)` written explicitly — `I2S_PDM_RX_SLOT_DEFAULT_CONFIG` survives in v6.0.2 only as a `@cond` alias. The S3 defines `SOC_I2S_SUPPORTS_PDM2PCM`, so the hardware decimator delivers PCM and `data_fmt = I2S_PDM_DATA_FMT_PCM`. `int16 → float × (1/32768)` happens once, at the [`audio_source`](../../firmware/twatch-s3/components/audio_source/README.md) seam; everything downstream is `float` in `[-1, 1]`.
  3. **MAX98357A on I2S1, standard (Philips) mode**, `i2s_channel_init_std_mode()`, BCLK 48 / WS 15 / DOUT 46 — two independent `i2s_new_channel()` calls with different `i2s_chan_config_t.id`. The amp exists in v1 for the **calibration-tone** path (it validates FFT bin mapping and the acoustic-path geometry), not for playback features.
  4. **Default 32 kHz with `I2S_PDM_DSR_8S` ⇒ PDM CLK 2.048 MHz.** `i2s_pdm_rx_calculate_clock()` sets `bclk = sample_rate × I2S_LL_PDM_BCK_FACTOR × (DSR_16S ? 2 : 1)`, and `I2S_LL_PDM_BCK_FACTOR` is 64 on the S3 — so 32 kHz/`DSR_8S` = 2.048 MHz, comfortably mid-window in the SPM1423's 1.0–3.25 MHz clock range, and 16 kHz Nyquist still covers ring (2.5–3.5 kHz), twang (3.5–5 kHz) and the 5–8 kHz noise band. 16 kHz/`DSR_16S` reaches the same 2.048 MHz and is the low-power preset option; LilyGoLib's 16 kHz ceiling is a legacy artefact of its own driver, not a mic limit.
  5. **48 kHz is gated on measurement, not on arithmetic.** 48 kHz/`DSR_8S` needs **3.072 MHz**, which leaves only ≈ 178 kHz below the datasheet's 3.25 MHz maximum — 5.5 % of the ceiling, the same margin the [pins doc](../hw/twatch-s3-pins.md) quotes as "5.8 %" relative to the 3.072 MHz clock — and that maximum is a revision-pinned datasheet value read from a raster table, not something we have measured. The trigger is [experiment 0001](../validation/experiments/0001-pdm-mic-in-situ-characterization.md) clause 4: capture at 48 kHz/`DSR_8S` and at 32 kHz/`DSR_8S`, same geometry — **pass** = no dropouts (the overrun counter, item 8, reads zero), noise floor within 1 dB of the 32 kHz capture, no clock-related spurs ⇒ 48 kHz becomes a selectable preset rate (ADR 0010 schema); **fail or marginal** ⇒ roadmap threshold **T3**, cap at 32 kHz and drop the 48 kHz option from the schema. Until it runs, no document may state 48 kHz as available.
  6. **DC removal is software, in the capture path, and declared.** A first-order DC blocker (or an RBJ high-pass, `dsps_biquad_gen_hpf_f32(c, f_hz/fs, 0.7071f)` — normalised frequency, `Fs = 1`) runs on the float block before windowing, corner **20 Hz (prov.)**, i.e. below the 65 Hz (C2) f0 floor of the validation plan. Its coefficients are a `spectral_core`/ADR 0006 artefact so watch and host compute the same filter to a stated tolerance, and the take header records which filter was applied. Raw (pre-blocker) mean and RMS are logged for experiment 0001 — the DC offset the PDM2PCM filter leaves is a measured number, not an assumption (roadmap Q23), and the corner is raised only by measurement.
  7. **No NS, no AGC, no AEC — ever — in the analysis path.** No ESP-SR/ESP-ADF AFE, no vendor "voice enhancement", no compressor, no limiter (CLAUDE.md never-rule 8; the licence side is ADR 0004). The only permitted operations are linear and documented: DC removal, the minimum-phase mic EQ (ADR 0010's mic-EQ slot, fitted from experiment 0001), windowing, and a **fixed, logged** scalar gain. Clipping is *flagged* (`|s| ≥ 0.99` FS), never silently tamed.
  8. **DMA and ring buffers are internal.** Everything DMA-facing is `MALLOC_CAP_INTERNAL | MALLOC_CAP_DMA`; PSRAM is never a DMA source or destination ([pitfalls D5](../devenv/pitfalls.md#d-memory-placement-and-runtime)), which is also why `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL` / `…_RESERVE_INTERNAL` are set. `dma_desc_num` × `dma_frame_num` is sized from the preset hop (the driver's own defaults, 6 × 240, are 90 ms at 16 kHz — the precedent project's comment claiming 30 ms is wrong by 3×). `i2s_event_callbacks_t.on_recv_q_ovf` is **always** registered: an unregistered overrun is a silent one, and the dropped-frame metric depends on it. `i2s_channel_read()` is called with a finite timeout, never `portMAX_DELAY` (a stalled I2S must surface as an error, not as a task blocked forever past a watchdog that only watches idle tasks). DSP task on core 1, UI on core 0.
  9. **No SPM1423 constant is baked into the capture path.** Sensitivity (−22 dBFS @ 94 dB SPL), SNR (61.5 dB(A)), AOP and the response curve live in the preset/mic-EQ data, behind the `audio_source` interface — the part is obsolete at distributors and a second source (TDK T3902) would change all of them.
  10. **Open, and stated as open: which AXP2101 rail powers the SPM1423** (and the MAX98357A). The *pin-voltage* half of that question is closed — VDD_SPI is eFuse-forced to 3.3 V on this unit, so GPIO47/48 are 3.3 V-domain pins ([ADR 0016](0016-backlight-gpio45-vdd-spi-strap.md), [`docs/hw/README.md`](../hw/README.md) ledger) — but the *rail* half now has strong code evidence short of the schematic: LilyGoLib's `RecordWAV` example records **before** `powerControl(POWER_SPEAK, true)`, and `initPMU()` disables DLDO1 while TTGO's branch carries `enableDLDO1(); //! Speaker` — so **DLDO1 is the amplifier rail and the microphone sits on an always-on 3.3 V rail** ([study notes](../reference-projects/notes/lilygolib-axp2101_notes.md) §5, added 2026-08-21; still to be confirmed against the schematic, roadmap Q14/H2, phase D3/D4). Consequences either way: firmware does **not** attempt to power-gate the microphone, the capture-path power budget carries a `TBD`, and I2S0 is enabled only after the PMU bring-up sequence has settled. The PDM **slot mask** is equally open (`I2S_PDM_SLOT_LEFT` vs `RIGHT`, E2 item H7): bring-up tries both before anyone calls a silent mic a dead mic.
- **Alternatives:**
  - *Mic on I2S1, amp on I2S0.* Not an alternative — the driver's two `ESP_RETURN_ON_FALSE` guards reject it. Recorded because the allocation looks arbitrary until you hit them.
  - *One full-duplex port (mic + amp on I2S0).* Rejected: full duplex shares BCK/WS and one slot/clock configuration, which PDM RX and standard TX can never agree on, and it would force one direction into slave role. Trigger to revisit: none on this silicon.
  - *Hardware PDM high-pass instead of a software blocker.* Not available — `SOC_I2S_SUPPORTS_PDM_RX_HP_FILTER` is absent for the S3 at v6.0.2. Trigger: a future target that defines it; even then software DC removal likely stays, because the host must reproduce the same filter.
  - *ESP-SR AFE (NS/AGC/AEC) or ESP-ADF in the analysis path.* Rejected permanently: non-linear, signal-dependent processing destroys exactly what is measured (spectra, formants, H1–H2, band ratios); the AFE is kept only as a **resource yardstick** (9–32 % CPU, 0.7–4 MB PSRAM on the S3), and its field-of-use licence is excluded from the firmware by ADR 0004. Trigger: none for analysis. A future voice-command feature would consume a *separate copy* of the stream and never the analysis stream.
  - *48 kHz as the default rate.* Deferred, not rejected — see decision 5; trigger is experiment 0001 clause 4 / threshold T3.
  - *Raw PDM capture (`I2S_PDM_DATA_FMT_RAW`) with our own decimation chain.* Rejected for v1: it would make the decimation filter's passband ripple and group delay explicit and ours, at the cost of a ≈ 3 MHz bit-stream, a CIC/FIR chain to validate, and internal-RAM bandwidth the FFT needs. Trigger: experiment 0001 shows the PDM2PCM filter's response materially distorting the 2.5–5 kHz band (it measures the composite response anyway).
  - *`esp_codec_dev` as the capture abstraction.* Deferred: the `audio_source` seam is needed regardless for the `file_blob` and `synthetic` back ends (QEMU emulates no I²S; the digital-injection path bypasses the mic). It remains a candidate *implementation* of the `pdm_mic` back end. Trigger: `twatch_bsp` wanting its gain/volume API.
  - *16 kHz default (LilyGoLib's rate).* Rejected as the default: 8 kHz Nyquist truncates the twang band and the 5–8 kHz noise band. Retained as a low-power preset option at `DSR_16S`.
- **Consequences:**
  - (+) The port allocation, the slot width and the clock formula are all derivable from the pinned driver, so the capture configuration is reviewable against source, not against folklore — and it was link-checked by the gate before any feature code existed.
  - (+) Every conditioning step is linear, fixed and recorded in the take header, so the host can reproduce (or invert) exactly what the watch did — the precondition for the "vs Praat" claim on the injection path.
  - (+) 2.048 MHz sits mid-window in the mic's clock range, and the same clock is reachable two ways (32 kHz/`DSR_8S`, 16 kHz/`DSR_16S`), which makes the DSR path itself falsifiable during bring-up.
  - (−) 16-bit is a hard ceiling: no 24-bit headroom trick, no gain staging in the ADC. Loud phonation near the AOP is handled by distance and by the clipping flag, not by gain — and the flag's true-positive rate becomes a validation row.
  - (−) No hardware HPF means every capture carries a DC offset until software removes it, and that blocker is one more filter that must match between watch and host — a golden-file tolerance row that would not exist on a chip with the HP filter.
  - (−) The sample rate stays *two-valued* until threshold T3 resolves: the preset schema (ADR 0010), the bin-mapping tables and the FFT window tables must tolerate both 32 kHz and 48 kHz. That is real design debt carried for hardware-time reasons.
  - (−) The mic's rail is unknown, so the microphone cannot be power-gated in v1 and the capture-path term of the power budget is a `TBD` against a ≥ 3 h autonomy target.
  - (−) The slot mask is unknown until the first capture, and the failure mode (silence) is indistinguishable from a dead microphone — a bring-up trap that costs time exactly once if the procedure is not followed.
  - (−) The PDM2PCM decimation filter's response is not published by Espressif; it is folded into the measured in-situ response and cannot be separated from the mic and the case. Every "mic response" statement in this project is therefore a *path* response.
  - (−) The part is obsolete: a second-source swap on a later board revision changes sensitivity, SNR and AOP and invalidates the fitted EQ, per unit.
  - Flagged as a validation item: the 48 kHz clause is measured by [experiment 0001](../validation/experiments/0001-pdm-mic-in-situ-characterization.md) (clause 4, threshold **T3**); the rows *Sample-rate error*, *Noise floor / EIN*, *AOP / clipping flag*, *Displayed spectral dynamic range* and *Dropped-frame rate* of the [validation plan](../validation/README.md) are the metrics this ADR commits to, and the ADR is amended with the measured LF corner, DC offset and 48 kHz verdict when that experiment runs.

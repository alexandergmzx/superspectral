# 0021 — The founding document's web application is built in full under `host/`: a browser-native live analyzer that is the host's UI and a second injection-path instrument, never a wearable claim

- **Status:** **accepted** (owner decision 2026-08-22; written 2026-08-22 — the research-question closing clause is reworded by this record's decision 9, wording chosen by the owner on the same day)
- **Date:** 2026-08-22
- **Context:** The founding research document ([§B](../research/00-linux-analyzer-architecture-and-build-guide.md)) is a *Linux* analyzer: a browser live path (`getUserMedia` with raw constraints → AudioWorklet → FFT → WebGL waterfall + Canvas2D spectrum at 50 Hz, six JSON presets, f0 / ring / F1–F2 overlays) and a Python offline path (FastAPI: `/presets`, `/analyze` with parselmouth + librosa, `/separate` with Demucs, DTW alignment, LTAS / SPR / H1–H2 overlays against a separated stem), with a build roadmap M0–M4 and a pre-committed threshold — *if browser f0 cannot hold 50 Hz, move f0 server-side*. That web application was the project's first deliverable.

  [ADR 0002](0002-companion-architecture.md) moved the *live path* onto the T-Watch S3 and kept the Python half; in doing so it dropped the browser half entirely — decision 4 said "no live host view", the rejected alternative *Browser-first live path, watch as a microphone* dismissed both halves of the founding recommendation in one sentence, and [`host/README.md`](../../host/README.md) followed with "not a browser app … if a UI is ever added here, it is an offline viewer". Nothing in that chain argued against the web application **as the host's own instrument**; it argued against it **as the wearable**. On 2026-08-22 the owner decided that the founding document's web application is the spine of the project and is to be built in full.

  Four facts make this a decision rather than scope creep:

  1. **The host has no user interface and the offline compare mode has no user.** `host/README.md` plans `analyze/` and `compare/` modules with no way to look at their output; the founding document's offline compare mode *is* the interface those modules need.
  2. **The injection path has one instrument.** [Proposal §4.1](../proposal/01-super-spectral-proposal.md)'s digital-injection path runs corpus WAVs through the watch's `file_blob` and compares against the Python oracle and the Praat goldens ([ADR 0009](0009-golden-file-strategy.md)). A second, independent implementation of the [ADR 0006](0006-fft-normalisation-and-window-conventions.md) conventions — different language, different FFT kernel, IEEE double throughout — run on the same Tier-0 files against the same goldens, catches a convention bug in *either* the C or the Python side. The web application's injection mode supplies that instrument at no hardware cost.
  3. **A rehearsal-room tool exists before firmware M1 does, without touching the watch.** [ADR 0013](0013-native-linux-simulator-target.md) already records that days when the watch may not be touched are normal here. The web application runs on any laptop and, over the LAN, on a phone — the founding document's "open it from a phone" property.
  4. **The wearable claim is untouched.** [Proposal §1](../proposal/01-super-spectral-proposal.md) lists four reasons a phone or laptop analyzer fails in a rehearsal room: it needs a surface and a hand, it is not glanceable while singing, its audio front end is not yours, it is a second device to manage. Every one of them remains true of this web application; they are the reasons it is not the product. The research question's prohibition therefore binds the **watch's numbers**, and must say so in words that survive a live analyzer existing on the host.

- **Decision:**

  1. **Scope — the founding document's §B, in full.** Live path: `getUserMedia({audio: {echoCancellation: false, noiseSuppression: false, autoGainControl: false, channelCount: 1}})` → AudioWorklet ring buffer → DC blocker → window → FFT → `|X|²` → dBFS in TypeScript → WebGL scrolling waterfall + Canvas2D spectrum line, peak markers, hold, smoothing, the six presets, the clipping flag (`|s| ≥ 0.99` FS), and the live overlays (time-domain f0 with note and cents, ring / twang band energy, `L_Aeq`). Offline compare mode: FastAPI `/presets`, `/analyze` (parselmouth f0 contour, Burg formants, LTAS), `/separate` (Demucs `htdemucs`, vocals two-stem), DTW alignment (`librosa.sequence.dtw`) of a take against the separated stem, aligned overlays (f0, LTAS, SPR / ring ratio, H1–H2 over stable voiced regions), per-phrase segmentation. The founding document's M0 peak-frequency printer lands as `spectral-web peak`. Its **M5** (native DSP core behind the same signatures) is **out of scope** and stays so unless a profile demands it. Layout: front end under `host/web/` (Vite + TypeScript), backend under `host/src/spectral_host/web/` (FastAPI + uvicorn).
  2. **Browser-native live DSP, held to the Python oracle by the committed golden set.** The live path never streams audio to Python. The [ADR 0006](0006-fft-normalisation-and-window-conventions.md) conventions are **re-implemented in TypeScript** — periodic cosine-sum windows built from the preset's own `coefficients` (never a library window by name), the float64 table rounded once to float32 so the digest is the device's, Heinzel S1/S2 with the factor 2 on bins `1 … N/2−1` only, 0 dBFS = full-scale sine, `int16 → float × 1/32768` once at the WAV reader, `Math.log10` in double (no fast-log row) — and held equal to `spectral_host.spectrum` through the **same** `host/golden/outputs/tier0-synthetic` set the watch is held to ([ADR 0009](0009-golden-file-strategy.md)). The rows are added to [`golden-files.md`](../validation/golden-files.md): window table digest per `(family, N)` **exact**; per-bin magnitude vs the oracle `atol = 0.01 dB` for bins ≥ −80 dBFS `(prov.)`; interpolated peak frequency ≤ 3 cents; browser f0 vs the Praat golden ≤ 5 cents `(prov.)` in its **own** row. The FFT kernel is not mandated — a hand-written radix-2 complex-`N/2` plus the real-packing split (the structure [ADR 0006](0006-fft-normalisation-and-window-conventions.md) D5 chose for the watch) or an MIT kernel ([06 #62](../bibliography/06-reference-projects.md)) `(prov.)`; whichever is used passes the rows or it does not ship. **The Python oracle is the only arbiter**: every implementation is compared to it, never to another implementation, so the agreement matrix stays a star and there is no watch-vs-browser row.
  3. **The web application is the host's user interface and a second injection-path instrument — never a wearable claim.** It joins [proposal §4.1](../proposal/01-super-spectral-proposal.md)'s digital-injection path as the second thing that can run a Tier-0 or corpus WAV through the ADR 0006 conventions against the same goldens. Its own latency (microphone to pixel in a browser) and sustained refresh are **measured and reported, never claimed**: they appear in the *Host web application metrics* block of [`../validation/README.md`](../validation/README.md) with the target cell reading *measured, no claim*, are reported per browser and OS, and carry no research-question bound. Its *acoustic* numbers carry the capture-chain linearity verdict of decision 8 and never enter the acoustic-path factorial matrix of [proposal §4.4](../proposal/01-super-spectral-proposal.md), which is the watch's. **No number produced by the web application may be quoted for any bound of [proposal §1](../proposal/01-super-spectral-proposal.md).**
  4. **Licence: GPL-3.0-or-later for all of `host/web/`; permissive npm dependencies only; AGPL forbidden.** The front end is the user interface of the GPL program that serves it, so it stays inside the directory boundary of [ADR 0004](0004-split-licensing.md): every `.ts`, `.css` and `.html` file carries `SPDX-License-Identifier: GPL-3.0-or-later`; `package.json`, `package-lock.json`, `tsconfig.json` and static assets are annotated by `host/REUSE.toml`. npm dependencies admit **MIT, ISC, 0BSD, BSD-2-Clause, BSD-3-Clause, Apache-2.0, CC0-1.0, Unlicense, BlueOak-1.0.0, Python-2.0, Zlib and CC-BY-4.0** and nothing else; **AGPL-3.0 is forbidden** — audioMotion-analyzer ([06 #66](../bibliography/06-reference-projects.md)) is the named do-not-use, because a served web application is exactly the case its network clause reaches; GPL and LGPL npm packages are refused too, not because the GPL tree could not carry them but so that the allowlist stays one line a reviewer can check. A licence gate over `package-lock.json` runs in CI and **fails closed** on an unknown or absent licence; `npm ci` against the committed lockfile is the only install path. The W4 Python additions — librosa (ISC, [06 #34](../bibliography/06-reference-projects.md)), demucs (MIT, [06 #59](../bibliography/06-reference-projects.md)), torch (BSD-3-Clause (verify) — no bibliography row of its own; it arrives as demucs's dependency, and its `LICENSE` is read at the pinned version before the flag clears) — enter `host/pyproject.toml` and `uv.lock` under the same discipline. Pretrained Demucs weights are **data**: fetched at first run into the data directory of decision 8, never committed, their terms read from the release page at pin time; any figure computed on a separated stem inherits the quarantine question of [proposal §4.5](../proposal/01-super-spectral-proposal.md) until those terms are quoted.
  5. **Relation to the watch: no live link; the contract stays files.** Takes in, reports out, presets shared — nothing else. [ADR 0002](0002-companion-architecture.md) decision 4 is **amended** from "no live host view" to "**no live link between watch and host**", and its decision 3 from "the host never sees live audio" to "the host never sees **the watch's** live audio". No transport of audio or spectra from the watch to a browser exists in v1: it would need the radio [ADR 0017](0017-no-radio-in-v1-trimmed-component-set.md) excludes, and it would be the research-question violation the prohibition names. When `take-format.md` exists, the web application's offline compare reads takes through the same reader as the CLI — files on disk; until then it accepts WAV uploads.
  6. **Relation to [ADR 0013](0013-native-linux-simulator-target.md): two different programs, both may exist.** `host-sim` renders the **watch's own `ui` component** through LVGL's SDL driver — Apache-2.0, plain CMake, outside `host/`, an oracle for the watch's pixels and nothing else. The host web application is the founding document's analyzer with its own renderer — GPL-3.0-or-later, under `host/`, an instrument in its own right. Neither substitutes for the other and ADR 0013's three-lane table is unchanged. **Vocabulary, from here on:** `host/` is the GPL directory · the *host lane* is ADR 0013's native-Linux build · `host-sim` is the SDL watch-UI simulator · **the host web application** (short: *the web app*) is this record's program.
  7. **The six presets are the single source of truth, served from `protocols/presets/` by the backend.**
     **(a)** `GET /api/presets/{id}` returns the canonical file **byte-identical** after `spectral_host.presets.load_preset` has proved it (V0/V1/V8/V9); the sha256 of each is displayed in the interface beside the preset name. The front end never ships its own copy and the bundler never embeds one; drift is a red test, not a fork.
     **(b)** `targets: ["watch","host"]` ([ADR 0010](0010-preset-schema.md)) is not extended: **"host" now means the CLI and the web application alike**. The five presets with `refresh_hz_target` are the web application's live presets; `stem_analysis` (host-only, 48 kHz) is its offline-compare preset.
     **(c) Sample rate.** The presets state 32 kHz and browsers default to 44.1 or 48 kHz. Live mode constructs `new AudioContext({sampleRate: preset.analysis.sample_rate_hz})` and **asserts** the resulting `AudioContext.sampleRate`; on a mismatch it **refuses to start** and names both rates — the watch's validate-and-reject rule, applied here because a silent browser resampler in the live chain would make `bin_width_hz` and `enbw_hz` fiction. No resampler is added in W1–W3; if one ever is, it is declared in the capture-chain panel and in every report ([ADR 0003](0003-microphone-path.md) d.7's rule: linear and declared). Injection mode **never** uses `decodeAudioData` (which resamples to the context rate and converts by an unstated convention): a TypeScript WAV reader parses the int16 PCM itself and feeds the same DSP module in a Worker with no audio graph, so *the same Tier-0 files against the same goldens* is literally true.
     **(d) Smoothing.** `analysis.smoothing` is the weight of the **previous** frame: `P̂[k] ← s·P̂[k] + (1 − s)·P[k]`, in linear power ([ADR 0006](0006-fft-normalisation-and-window-conventions.md) D8), so a larger value is smoother — Spectroid's sense, and the reading every consumer must share. `(prov.)` until it is written into [`preset-schema.md`](../../protocols/specs/preset-schema.md) §4; the schema says only "exponential coefficient" today, and three implementations were about to guess.
     **(e) Band edges.** Ring and twang edges are read from one shared `(prov.)` constant (the founding document's 2.5–3.5 kHz and 3.5–5 kHz), never from a preset — the schema refuses band edges on purpose, and [ADR 0008](README.md) owns the answer.
  8. **Secure context, raw capture, data directory.** `navigator.mediaDevices` is `undefined` on insecure origins other than `localhost`, so phone-on-LAN needs HTTPS: **mkcert** mints a locally trusted certificate for the laptop's LAN address and uvicorn serves it with `--ssl-certfile` / `--ssl-keyfile`; Chrome's insecure-origin flag is a development fallback and is never documented as the way in. **Phone-on-LAN is a requirement, not a nicety** (owner, 2026-08-22): W2 is not done until the waterfall runs on the owner's phone through that certificate. Raw-capture constraints are **mandatory and insufficient** — some drivers and browsers process regardless ([proposal §1](../proposal/01-super-spectral-proposal.md) reason 3; the founding document's own caveat) — so the app reads back `track.getSettings()` and shows what it actually got, and a **capture-chain linearity test** (a known tone at two levels 20 dB apart through the live path; the step must reproduce within ±0.5 dB `(prov.)` and the noise floor must not move with the tone) is a validation row, runs before any acoustic number from the web application is reported, and its verdict — *unprocessed* or *processed* — travels with every such number (experiment 0006). The data directory — uploads, separated stems, model weights, ingested takes — defaults to `$XDG_DATA_HOME/superspectral/`, is overridable, is **never inside the repository** (the server refuses one that is) and is never committed `(prov.)`.
  9. **Milestones are W0–W4 on the roadmap's new track W; the research question's closing clause is reworded.** Host milestones are **never H-numbered** — H1–H18 are the roadmap's hardware questions; the existing "H0" of the golden-file lane stays as a historical label, and `host/README.md`'s planned H3/H4 modules become W4. **W0** peak CLI + both skeletons + `/presets` · **W1** live spectrum against the goldens · **W2** waterfall + preset switching + injection mode + phone-on-LAN · **W3** f0 / ring / F1–F2 overlays · **W4** offline compare. The gates are in the [roadmap](../roadmap/documentation-roadmap.md) track W. The closing clause of the research question — "*with all real-time DSP on-device and the host used only for offline analysis of recorded takes*" — becomes false the moment the host has a live analyzer of its own, and is replaced by the owner's chosen wording: "*with all real-time DSP behind these bounds on-device, the host never in the watch's live loop, and files the only contract between them*". Every number in the question is untouched; the clause now states a **testable property** (the host is absent from the loop; the contract is files) instead of a feature restriction on the host. It is applied byte-identically to [the proposal](../proposal/01-super-spectral-proposal.md), [`CLAUDE.md`](../../CLAUDE.md), [`README.md`](../../README.md) and [`research-statement.md`](../proposal/research-statement.md) in the same commit as this record; the **freeze** of the question remains the author's act, unchanged by this ADR.

- **Alternatives:**
  - *Stream audio to Python and compute the live path there* (the founding document's own "when you'd still stream to Python"). **Rejected for live, kept for offline.** The founding document's verdict stands — "you gain consistency, you lose latency and the trivial phone-deploy story" — and it would make the web app a thin client of the oracle, destroying the second-instrument property of decision 3. `/analyze` *is* this option, for the offline path, where it belongs. **Revisit trigger:** the TypeScript implementation cannot hold the 0.01 dB row, or browser f0 cannot hold 50 Hz on the owner's phone — the founding document's own pre-committed threshold; then f0 alone moves server-side and its row is annotated.
  - *A Friture-style desktop application (Python + Qt).* **Rejected.** Friture ([06 #32](../bibliography/06-reference-projects.md), GPL-3.0) already exists and stays read-only prior art; a desktop app forfeits phone-on-LAN, and its accessibility obligations have no standard to cite against — [03 #23](../bibliography/03-standards.md) is written for web content. **Revisit trigger:** none foreseen.
  - *Offline viewer only* (the position of `host/README.md` until this record). **Rejected by the owner, 2026-08-22.** It drops the project's first deliverable, leaves the injection path with one instrument, and leaves the singer without a tool until firmware M1 — which is gated on D6, experiment 0001 and ADR 0007.
  - *Browser-only, no backend — everything in WASM.* **Rejected.** parselmouth embeds Praat and Demucs needs torch; neither runs in a browser, and the goldens are generated by the Python side in any case ([ADR 0009](0009-golden-file-strategy.md)). **Revisit trigger:** never for Praat.
  - *The front end under Apache-2.0 outside `host/`* (a root-level `web/`). **Rejected.** It would be served by, and exist for, the GPL backend; splitting the licence across a served pair reintroduces the distribution question the directory boundary exists to avoid, and one licence per directory is what makes [ADR 0004](0004-split-licensing.md) a one-`grep` rule. **Revisit trigger:** a downstream permissive project needs only the live page — the sole author holds the copyright and can relicense the TypeScript DSP module then.
  - *A live link watch → browser* (the WebSocket dashboard of [06 #3](../bibliography/06-reference-projects.md)). **Rejected** three times over: [ADR 0017](0017-no-radio-in-v1-trimmed-component-set.md) (no radio), [ADR 0002](0002-companion-architecture.md) decision 4 (files, not a link) and the research question's prohibition. That project's ≈ 20 fps is a WebSocket and browser limit, not an FFT limit — which is the argument for computing the live path in the browser rather than shipping frames to it. **Revisit trigger:** the v2 radio decision, which supersedes ADR 0017 first.
  - *Use `host-sim` ([ADR 0013](0013-native-linux-simulator-target.md)) as the host's interface.* **Rejected.** It renders 240×240 pixels of the watch's own widgets; it is an oracle for the watch's screen, not an analyzer, and cannot show the offline compare mode at all. Not revisitable — the two programs answer different questions.

- **Consequences:**
  - (+) The injection path gains a **second instrument**: the same Tier-0 files and the same goldens through an independent TypeScript implementation of ADR 0006, so a convention bug in `spectral_core` or in the Python oracle no longer has only one witness.
  - (+) The rehearsal-room objections of [proposal §1](../proposal/01-super-spectral-proposal.md) remain true **of the watch claim** and are not contradicted — the web app is exactly the phone-or-laptop analyzer those four reasons describe, built deliberately, with its numbers labelled *measured, no claim*.
  - (+) The host's planned `analyze/` and `compare/` modules acquire a user interface and a user; the founding document's M0–M4 learning path is preserved as W0–W4.
  - (+) Progress on days when the watch may not be touched: W0–W3 need no hardware and no ESP-IDF environment.
  - (+) [ADR 0010](0010-preset-schema.md)'s schema is exercised by a second consumer with a different loader — the first real test of "the preset is the contract" beyond the watch's own validator; decision 7(d) is the first thing that test found.
  - (−) **A third front-end implementation to keep in agreement** — C `spectral_core`, the Python oracle, now TypeScript (four, counting esp-dsp `_aes3` against ANSI C). The mitigation is structural: every implementation is compared to the oracle and never to another, so the matrix stays a star, not a clique.
  - (−) **torch and Demucs weigh.** Hundreds of megabytes of dependencies, a model download at first run, CPU separation an order of magnitude slower than GPU, and CI that cannot run it — `/separate` is exercised through its 501 path in CI and the real path is a recorded manual run.
  - (−) A **third toolchain** (Node and npm) and a fourth CI lane; a lockfile that churns; an npm supply-chain surface the firmware never had. `npm ci` against a committed lockfile, `--ignore-scripts`, and the fail-closed licence gate are the whole mitigation.
  - (−) **The browser's capture chain is not ours.** Constraints are a request; the linearity test of decision 8 makes processing *visible*, it cannot remove it. A *processed* verdict on a given phone is a finding about that phone, and the web application's acoustic numbers there are worth exactly that.
  - (−) HTTPS and mkcert friction for phone-on-LAN, and a certificate per laptop that a third party must mint themselves.
  - (−) The word "host" now names three things; decision 6 fixes the vocabulary and every document this record touches uses it.
  - (−) A live analyzer on the host invites the shortcut the research question forbids. The guard is wording, not mechanism: decision 3's *measured, no claim*, decision 5's *no live link*, and the reworded prohibition of [proposal §1](../proposal/01-super-spectral-proposal.md).
  - (−) Scope grows while the Phase-0 definition of done is not green. The owner's ordering decision (2026-08-22) is that track W runs first and his own DoD items run in parallel; firmware stays parked until both are green.
  - (−) WCAG 2.2 ([03 #23](../bibliography/03-standards.md)) stops being an analogy and becomes an obligation of a shipped interface; EN 301 549 ([03 #24](../bibliography/03-standards.md)) applies the moment the application is offered in the EU.
  - Flagged as a validation item: this ADR **adds a metrics block** — *Host web application metrics* in [`../validation/README.md`](../validation/README.md) (spectrum vs oracle, window digest, peak frequency, browser f0 vs Praat golden, capture-chain linearity, mic-to-pixel latency *measured*, sustained refresh *measured*, preset byte-identity) and three rows in [`golden-files.md`](../validation/golden-files.md). Every latency or refresh cell in that block reads *measured, no claim* by decision 3, and experiments 0006 and 0007 are reserved for the two that need a rig.

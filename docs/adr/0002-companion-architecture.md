# 0002 — Companion architecture: the watch is the live path, the Linux host is the offline path, and a take file is the only contract between them

- **Status:** **accepted** (owner decision 2026-08-20; the split was already normative in [proposal §3.2](../proposal/01-super-spectral-proposal.md) and is the answer to question Q6 of the [roadmap](../roadmap/documentation-roadmap.md))
- **Date:** 2026-08-21
- **Context:** The founding research document splits its analyzer by physics — a browser live path (getUserMedia → AudioWorklet → FFT → WebGL, 50 Hz) and a Python offline path (parselmouth/Praat formants, LTAS/SPR, H1–H2, DTW, Demucs) — and is explicit about the trade-off of streaming raw audio to the offline half instead — "you gain consistency, you lose latency" ([research doc §B](../research/00-linux-analyzer-architecture-and-build-guide.md)). Super Spectral replaces the browser half with a sealed wrist device, which changes what *live* is allowed to cost. Four facts fix where the line falls:
  1. **Licence.** The offline half is worth having only because it is Praat: parselmouth embeds Praat (GPLv3), so it can never be linked into Apache-2.0 firmware. The boundary has to be a directory a reviewer can see ([`host/`](../../host/README.md), [ADR 0004](0004-split-licensing.md); 05 #55).
  2. **Compute and memory.** The FFT is not the bottleneck — real-4096 at 50 Hz is ≈ 6 % of one core `(prov.)` (02 #21, 06 #1) — but **internal SRAM is**: our esp-dsp study measures a real-8192 `fc32` pipeline at ≈ 160 KB with stock esp-dsp, ≈ 104 KB with our own `cplx2real` ([esp-dsp notes §4](../reference-projects/notes/esp-dsp_notes.md)), and PSRAM cannot substitute (≈ 32.5 / 56.8 MB/s, 06 #23) so it holds history, not working buffers.
  3. **Microphone.** One Knowles SPM1423HM4H-B PDM mic, −22 dBFS sensitivity, 61.5 dB(A) SNR, 16-bit PDM RX on I2S0 only, no hardware high-pass in the pinned IDF ([ADR 0003](0003-microphone-path.md); 01 #9, 02 #15, 02 #16). Nothing on the wrist is calibrated in-session, so every level-dependent readout is relative — and SPR in particular is uninterpretable without an SPL co-report (05 #36).
  4. **Link.** Since [ADR 0017](0017-no-radio-in-v1-trimmed-component-set.md) (verified in the build on 2026-08-21) the firmware contains no radio at all, so the *only* watch↔host link is the USB cable that is also the only recovery path ([ADR 0015](0015-anti-brick-policy.md)), and the only place a take can live is the 0x6D0000-byte (6.81 MiB) FAT `takes` partition frozen by [ADR 0014](0014-partition-layout-frozen.md).
- **Decision:** Two halves, one line, drawn once here.
  1. **The rule for the line.** A feature runs **on the watch** if and only if (a) its value depends on being live, and (b) it can be computed honestly from a single-microphone, uncalibrated, 16-bit capture inside the SRAM and latency budget. Everything else runs **on the host**, offline, on recorded takes. "Honestly" is doing work in (b): a metric whose interpretation needs an SPL co-report, a formant bandwidth, or a whole take is not made honest by fitting on the CPU.
  2. **All real-time DSP is on-device.** PDM capture → software DC removal → window → esp-dsp `fc32` FFT → magnitude / spectrogram / f0 / band energy → ST7789, DSP on core 1, UI on core 0 ([`firmware/twatch-s3/`](../../firmware/twatch-s3/README.md), [architecture tenets](../architecture/README.md)). Latency, refresh and autonomy are therefore properties of the firmware alone and are measured as such.
  3. **The host never sees live audio.** It sees takes. It is never required for live use: the watch does useful work with no phone, no PC and no radio.
  4. **The contract is files, not a link.** Take records and preset JSON, owned by [`protocols/specs/`](../../protocols/specs/README.md) (ADR 0010, ADR 0014). No RPC, no streaming, no live host view, no second transport.
  5. **The host is the reference, not a second implementation.** What the watch displays must be recomputable by the host from the same take; `spectral_core` is regressed against host-generated golden vectors to a stated tolerance (ADR 0009), under one shared set of FFT/window conventions (ADR 0006). The host does not reimplement the firmware's FFT to compare bit-for-bit.
  6. **No non-linear pre-processing on either side, ever** — no AFE/NS/AGC/AEC. It corrupts spectra, formants and H1–H2, which is the same reason the founding document disables `echoCancellation`/`noiseSuppression`/`autoGainControl` in the browser.
  7. **Transfer is USB and stays subordinate to recovery.** Whatever `take-transfer.md` chooses (USB MSC exposure of the FAT partition vs a console dump) must never disable the USB-Serial-JTAG console ([ADR 0015](0015-anti-brick-policy.md)).

  **The feature table is normative** ([proposal §3.2](../proposal/01-super-spectral-proposal.md) mirrors it and does not fork it; ✅ = ships there, ⚠️ = computed there but not the reported number, ✗ = never):

  | Feature | On-watch (live) | Host (offline, on takes) | Rationale |
  |---|:---:|:---:|---|
  | FFT magnitude spectrum, all six presets | ✅ | ✅ | 1.3–8.9 % of one core at 50 Hz for real N = 1024…8192 `(prov.)` (02 #21) |
  | Spectrogram waterfall (hardware-scrolled) | ✅ | ✅ | ≈ 480 B per new column with ST7789 vertical scroll (gated, threshold T4); ≈ 10 min of 256-bin history in PSRAM |
  | Peak markers, max-hold, exponential smoothing | ✅ | ✅ | negligible cost |
  | Time-domain f0 (MPM / YIN / dywapitchtrack) | ✅ | ✅ (pYIN / Praat reference) | ≈ 6 % of a core `(prov.)`; MPM needs ~2 periods, which is what fits a 20 ms hop (05 #8) — the host's HMM-smoothed pYIN (05 #10, 06 #34) is what a frame-independent on-device estimator lacks, and that gap is itself a reportable quantity |
  | Band energy: ring 2.5–3.5 kHz, twang 3.5–5 kHz | ✅ with the fitted mic EQ | ✅ | the mic's HF rise sits inside the twang band; the uncorrected value is always displayed next to the corrected one |
  | FHE (05 #37), Omori peak-to-peak SPR (05 #35) | ✅ relative, within-subject, within-session | ✅ with an SPL co-report | LTAS level tracks loudness strongly up to 4 kHz (05 #36) |
  | Octave / fractional-octave bank (decimation cascade) | ✅ | ✅ | IIR cascade, ≈ 1.4 % of a core for four stages `(prov.)` |
  | A/C/Z weighting, Leq | ✅ dBFS only | ✅ | relative unless a Class-1 calibrator has been applied in-session (01 #30) |
  | Low-order LPC F1/F2 overlay | ⚠️ marginal | ✅ Praat Burg + FormantPath | hand-ported (no LPC in esp-dsp), degrades at high f0 (05 #16, 05 #17) — an overlay, never the reported number |
  | Praat-grade Burg formants, FormantPath ceiling optimisation | ✗ | ✅ | the golden-file reference itself (05 #55) |
  | LTAS / SPR over whole takes | ⚠️ accumulate only | ✅ | cheap to accumulate on-watch; the *interpretation* needs the SPL co-report (05 #36) |
  | H1–H2 with Iseli–Alwan correction; Kreiman 4-parameter slope | ✗ | ✅ | needs F1–F3 **and their bandwidths** (05 #20, 05 #23) |
  | CPP / CPPS, AVQI-class composites | ✗ | ✅ | acoustic material only — no clinical claim ([ADR 0005](0005-no-clinical-claim.md)) |
  | DTW alignment, Demucs stem separation | ✗ | ✅ | the founding document's offline compare mode; the `stem_analysis` preset is host-only by definition |
  | On-device recording of takes | ✅ | ingests | OPUS at 48 kHz measured elsewhere at ≈ 25 % of a core and ≈ 29 KB, which coexists with a 6 % FFT load (02 #19) — but see the format consequences below |
  | AFE / NS / AGC / AEC (esp-sr) | ✗ never | ✗ never | non-linear; corrupts spectra, formants and H1–H2 |

  **What the split requires of the record format** (the format itself is owned by [`protocols/specs/`](../../protocols/specs/README.md); these are the constraints this ADR imposes on it):
  - `TAKE_HEADER` must carry everything needed to make a host recomputation *comparable*: preset id **and** the sha256 of the preset JSON, mic-EQ id, nominal sample rate and (once measured) the ppm correction, bit depth, RTC start time, device id, and the writing build's `app_elf_sha256`. A take whose analysis settings cannot be reconstructed is not evidence.
  - `PCM_BLOCK` is **raw 16-bit PCM by default and bit-exact**, because the digital-injection path replays it through `file_blob` — that replay is what makes "the host recomputes what the watch displayed" a testable claim rather than a slogan. Compression is ADR-gated: OPUS is lossy and disqualifies the take from bit-exact replay.
  - `FEATURE_FRAME` records **what was displayed**, frame by frame, so watch and host can be compared per frame rather than per take.
  - **Capacity is the binding number, and it is small.** 6.81 MiB of `takes` ÷ 64 KB/s = **≈ 112 s at the 32 kHz default** (≈ 74 s at 48 kHz, ≈ 223 s at 16 kHz), before FAT overhead and before `FEATURE_FRAME`/`EVENT` records share the file. A take is a phrase, not a rehearsal.
  - **Transfer is slow.** The only USB-Serial-JTAG throughput measured on this unit is the 16 MB factory read-back of 2026-08-20 at ≈ 10 KB/s ([`docs/hw/README.md`](../hw/README.md)) — a floor, not the CDC bulk rate, but at that floor a full `takes` partition is ≈ 13 min. This is the argument for MSC exposure of the FAT partition in `take-transfer.md`, and against any design that transfers takes routinely.
  - Every on-disk struct keeps its `_Static_assert`ed size; changing a layout is an ADR plus coordinated commits across firmware, host, validation and the test vectors.

  **If the microphone proves inadequate — roadmap threshold T2.** [Experiment 0001](../validation/experiments/0001-pdm-mic-in-situ-characterization.md) decides it in Phase 1. T2 trips if the in-situ 100 Hz–8 kHz response falls outside the envelope a minimum-phase IIR of order ≤ 8 can flatten to ±1.5 dB, **or** a resonance exceeds +6 dB inside 2.5–5 kHz, **or** A-weighted EIN exceeds 35 dB(A) SPL. The pre-committed consequence is a **host-first pivot**, executed as an *amendment to this ADR* (never a silent edit of the table above):
  - **Moves to host-offline:** every timbre and level metric — ring/twang band ratios, FHE, SPR, fractional-octave levels, A/C/Z weighting. On the watch they survive at most as an explicitly uncalibrated preview, or are removed from the display.
  - **Stays on the watch:** capture, FFT spectrum, spectrogram, time-domain f0, and therefore the latency, refresh and autonomy bounds — a poor magnitude response does not destroy periodicity, so the f0 claim is re-derived, not abandoned (an EIN failure separately costs the softest-phonation claim).
  - **Paperwork:** the research question is restated to f0 + latency + autonomy, proposal §1 and §7.1 are rewritten, and the [roadmap](../roadmap/documentation-roadmap.md) T2 row is annotated with the date it tripped.
- **Alternatives:**
  - *Stream audio to the host and compute everything there* (the founding document's "when you'd still stream to Python" option). Rejected: it answers a different research question — the RQ requires all real-time DSP on-device — and on this hardware it needs a radio (excluded by [ADR 0017](0017-no-radio-in-v1-trimmed-component-set.md)) or a permanent cable, while adding latency to the one number the product is judged on. Revisit trigger: a v2 phone companion, which supersedes ADR 0017 first.
  - *Port Praat-grade formants to the watch and have one implementation.* Rejected on licence and on method: parselmouth/Praat is GPLv3 and cannot enter the Apache-2.0 link line ([ADR 0004](0004-split-licensing.md)), and a hand-port would be a second implementation with nothing left to be the reference. Low-order LPC stays a marginal **overlay** (05 #16). Revisit trigger: none foreseen — an on-device formant tracker would need its own validation ADR and its own golden reference.
  - *Browser-first live path, watch as a microphone* (the founding document's own recommendation). Rejected: the watch is the product, and a phone in the hand defeats the hands-free singing use the interaction model is built around ([ADR 0012](0012-hands-free-interaction.md), proposed).
  - *Mirror every host analysis on the watch "for consistency".* Rejected: two implementations of one metric produce two answers and no arbiter. The watch is regressed against host golden vectors instead (ADR 0009).
  - *Run the offline analysis on-watch as an overnight batch over the recorded take.* Rejected for v1: it still has no Praat, it spends the battery the autonomy bound is measured on, and it would need the formant tracker the previous alternative rejected. Revisit trigger: a validated on-device formant tracker **and** a take format long enough to be worth batching.
  - *A BLE or Wi-Fi transfer path.* Deferred, not rejected — it is an ADR 0017 supersession, and it must be benchmarked against the audio-dropout metric before any radio task shares a core with the audio pipeline.
- **Consequences:**
  - (+) The research question becomes answerable: latency, refresh and autonomy are properties of the firmware alone, measured on a device with no host in the loop.
  - (+) The licence boundary is a directory boundary, so the GPL half can use the best available tool (Praat) while the firmware link line stays permissive ([`host/`](../../host/README.md), [ADR 0004](0004-split-licensing.md)).
  - (+) Every number the watch shows has an offline arbiter that works from the same bytes, which is what makes the golden-file strategy (ADR 0009) possible at all.
  - (−) Two implementations of the shared front end (window, normalization, dB reference) must agree to a stated tolerance forever. ADR 0006 and the whole golden-file apparatus exist **only** because of this split.
  - (−) Takes are phrases, not sessions: ≈ 112 s at 32 kHz in the frozen `takes` partition. Any workflow that assumes a rehearsal's worth of audio on the wrist is out of scope until the partition is rebalanced (which ADR 0014 permits only before shipping).
  - (−) Transfer is manual, cable-bound and slow (≈ 13 min for a full partition at the measured USB-Serial-JTAG floor). The offline path will be used rarely, so it must be worth the walk to the desk.
  - (−) The most interesting voice-science numbers (H1–H2, Kreiman slope, CPP, FormantPath) are never visible while singing. The live display is deliberately the weaker instrument.
  - (−) On-watch SPR/FHE/ring readouts are relative, within-subject and within-session by construction — a hard limit the UI must state, not hide (architecture tenet 7).
  - (−) The record format has to be frozen early, before any firmware writes a take, and every later change costs a coordinated multi-directory commit plus an ADR.
  - (−) The project maintains two toolchains, two licences and two CI lanes (ESP-IDF/C99 and Python/GPL) for one product.
  - (−) A feature table drawn before the microphone has been characterized will be wrong somewhere; T2 is the pre-committed correction for the case we can foresee, and amendment (not supersession) is the mechanism for the rest.
  - Flagged as a validation item: this ADR adds no new row to the [metrics table](../validation/README.md) — the watch↔host agreement rows (SPR, FHE, ring-ratio, median |Δcents| vs Praat) already carry it. What it adds is their **precondition**: the take round-trip and the bit-exact `PCM_BLOCK` replay, verified by the `## Verification hooks` of `protocols/specs/take-format.md`, and the T2 clauses of [experiment 0001](../validation/experiments/0001-pdm-mic-in-situ-characterization.md).

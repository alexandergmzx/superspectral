# 0004 — Split licensing: Apache-2.0 everywhere except `host/`, which is GPL-3.0-or-later so it may import Praat in-process; the firmware link line admits only MIT/BSD/Apache-2.0/CC0

- **Status:** **accepted** — in force since the initial commit `7bc8fa3` (2026-08-20, "Apache-2.0 with GPL-3.0 `host/` split"); this record was written 2026-08-21, after the history rewrite described below turned the redistribution half of the policy from a habit into a rule.
- **Date:** 2026-08-20
- **Context:** One repository holds two programs with incompatible dependency ecosystems.
  - The **watch** links ESP-IDF v6.0.2, esp-dsp (both Apache-2.0), LVGL, SensorLib, littlefs (MIT, littlefs core BSD-3-Clause) and should stay reusable: a PDM→FFT front end is the kind of component that gets upstreamed to ESP-IDF, and the `dmic_esp32.c` parked as shared future work in [ADR 0001](0001-toolchain-esp-idf-v6-pinned-environment.md) would go to Zephyr — both Apache-2.0 projects. Firmware is one statically linked monolith shipped over OTA to a sealed device.
  - The **host** ([`host/`](../../host/README.md)) exists to be Praat-grade: it imports parselmouth, which embeds Praat (GPLv3) **in-process** ([06](../bibliography/06-reference-projects.md) #31), alongside librosa and Demucs. There is no permissive substitute — "Praat-grade formants" means Praat's code, not a re-implementation.
  - Around both sits third-party material with its own terms: the embedded prior art is almost entirely GPL-3.0, AGPL-3.0 or unlicensed ([06](../bibliography/06-reference-projects.md) #39–#46), LilyGO's own software bundle mixes GPL-3.0, LGPL-2.1 and MIT in one repository (#45), the Arduino core is LGPL-2.1-only, ESP-ADF/ESP-SR carry a field-of-use "Espressif MIT" licence that is not open source (#47, [03](../bibliography/03-standards.md) #41), and the reference library is 46 vendor PDFs and papers whose redistribution terms range from CC BY 4.0 to unstated.

  Compatibility runs **one way**: Apache-2.0 code may be included in a GPLv3 work; GPL code may never be included in an Apache-2.0 work ([03](../bibliography/03-standards.md) #39, the FSF licence list plus the ASF's own GPL-compatibility page). A single licence for the whole repository therefore cannot be right for both halves — whichever one is chosen, one half pays.
- **Decision:** A split whose boundary is a **directory**, so that a reviewer can see it without reading a build file:
  1. **Apache-2.0 is the repository default** — firmware, `spectral_core`, `protocols/`, `dsp/`, `python-scripts/`, `host-tests/`, `tools/`, all documentation. Full text in [`LICENSE`](../../LICENSE). Every code/config file carries `SPDX-FileCopyrightText` + `SPDX-License-Identifier` ([03](../bibliography/03-standards.md) #40; the blocking `spdx-header` hook in [`.pre-commit-config.yaml`](../../.pre-commit-config.yaml), `reuse lint` at the manual stage until a `REUSE.toml` covers the Markdown library). [`NOTICE`](../../NOTICE) carries the third-party copyright lines Apache-2.0 §4(d) requires and is extended in the **same commit** that adds a dependency to [`main/idf_component.yml`](../../firmware/twatch-s3/main/idf_component.yml).
  2. **`host/` is GPL-3.0-or-later**, with its own [`LICENSE`](../../host/LICENSE), because of the in-process parselmouth import. Every file under it carries `SPDX-License-Identifier: GPL-3.0-or-later` in its header — in an HTML comment for the Markdown — except `LICENSE`, which is the licence text itself; and no file outside `host/` carries it. So the boundary is one `grep`, and its output is `host/` and nothing else. (The string also appears in *prose*, here and in [ADR 0009](0009-golden-file-strategy.md); the claim is about headers. Verified 2026-08-21.)
  3. **No code crosses the `host/` boundary in either direction.** Nothing outside `host/` imports it; nothing inside imports the rest of the repository. The only contract is files on disk — takes, presets, golden vectors, manifests — specified by [`protocols/specs/`](../../protocols/specs/README.md) ([ADR 0002](0002-companion-architecture.md)). Consequences that are easy to get wrong: [`host-tests/`](../../host-tests/README.md) is deliberately *outside* `host/` and Apache-2.0; `host/` is the sole exception to the "every Python file lives under `python-scripts/`" rule ([CLAUDE.md](../../CLAUDE.md#where-python-lives)), and moving Apache-2.0 tooling in there would relicense it.
  4. **The firmware link line admits only MIT, BSD, Apache-2.0 and CC0.** Nothing else enters `idf_component.yml`, `components/`, or the link line — no GPL, no AGPL, no LGPL, no field-of-use licence, no unlicensed code. The current set is Apache-2.0 or MIT throughout ([ADR 0001](0001-toolchain-esp-idf-v6-pinned-environment.md)); `esp-idf-sbom` enumerates and licence-checks it on every PR and with `--file-tags` on tags ([`ci.yml`](../../.github/workflows/ci.yml), [02](../bibliography/02-application-notes.md) #50).
  5. **GPL/AGPL/unlicensed code is read-only reference.** It may be read, run as a tool, and cited; it is never copied, vendored or translated. Named in [06](../bibliography/06-reference-projects.md) with an *Apache-2.0-compatible?* column: arduinoFFT (#42) and the `T-Watch-Deps` bundle that ships it (#45), cyberwisk's M5Cardputer analyzer (#39), ikostoski's mic-EQ/A-weighting IIR (#40), Friture (#32), Tony (#33), My-TTGO-Watch (#41, idea only → [ADR 0013](0013-native-linux-simulator-target.md)), `lockedmutex/esp32-fft` (#43, AGPL — listed so nobody re-discovers it), the unlicensed ESP32 spectrum/tuner cluster (#46, all rights reserved by default), WebPlotDigitizer (#38, AGPL, run as a tool — its CSV output is data, not derived code). Where such a project is the best explanation of an algorithm, the algorithm is re-derived from the standard or the paper instead ([03](../bibliography/03-standards.md) for filter coefficients, [05](../bibliography/05-papers.md) for DSP).
  6. **LGPL-2.1 `arduino-esp32` is avoided entirely**, not merely dynamically linked, for three independent reasons: §6a's relink obligation ([03](../bibliography/03-standards.md) #38) cannot be honoured meaningfully by a statically linked, sealed, OTA-updated binary — shipping linkable object files for a watch nobody can re-flash without the case open is a formality, not a freedom; its hidden `select`s force `WIFI_ENABLED`/`ETHERNET` into the build, which [ADR 0017](0017-no-radio-in-v1-trimmed-component-set.md) has now structurally excluded (`set(COMPONENTS main)`); and it anchors to ESP-IDF v5.5, against our v6.0.2 pin ([02](../bibliography/02-application-notes.md) #58). Pin numbers are therefore derived from the schematic (facts are not copyrightable) and LilyGoLib's MIT headers with attribution, never from `arduino-esp32/variants/` — [`docs/hw/twatch-s3-pins.md`](../hw/twatch-s3-pins.md), [pitfall H6](../devenv/pitfalls.md#h-ecosystem-and-expectations).
  7. **The "Espressif MIT" field-of-use licence is excluded** ([03](../bibliography/03-standards.md) #41): its "use only on Espressif chips" clause is not OSI open source, so ESP-ADF and ESP-SR stay yardstick documents ([06](../bibliography/06-reference-projects.md) #47) — a conclusion that agrees with the independent DSP reason for keeping AFE/NS/AGC/AEC out of the analysis path ([ADR 0003](0003-microphone-path.md)).
  8. **Reference documents follow the same discipline as code.** Only material whose terms permit redistribution is committed. [`docs/OCR/manifest.tsv`](../OCR/manifest.tsv) carries a `redistributable` column with exactly three values (`yes` | `no` | `unknown`, set through `python3 -m doc_ocr check --redistributable …`); **only `yes` is committed**. `no` and `unknown` documents stay on local disk, are listed in `.git/info/exclude`, and are represented in the repository by their sha256-keyed manifest row plus a `_notes.md` of derived facts. Extracted `.ocr.md` sidecars are gitignored because the extracted text inherits the source's terms ([`docs/OCR/README.md`](../OCR/README.md)). Paid standards are never committed even when bought; the LilyGO schematic is linked, not vendored; corpora keep their own ledger ([`datasets/README.md`](../../datasets/README.md), [10](../bibliography/10-datasets-and-ground-truth.md)).
  9. **Exceptions to item 4 are named here and nowhere else**, each with a resolution path and an owner ADR. One is open today: `lewisxhe/sensorlib` 0.4.1 is MIT and 15 of the 17 files in `src/bosch/bma4xx/` are BSD-3-Clause, but `bma423.c`/`bma423.h` — the BMA423 feature blob — carry the legacy 2017–2018 Bosch Sensortec "Disclaimer/Special" notice: no SPDX tag, no redistribution grant ([ADR 0018](0018-first-reference-project-study.md)). Our use is inside that notice's stated purpose (driving a genuine Bosch part on the vendor's own silicon) and the exposure is bounded to two files, but it is a real gap in item 4 and `NOTICE` currently mis-states them as BSD-3-Clause. Close it in this order: verify upstream `boschsensortec/BMA423-Sensor-API` and cite it if the grant is there ([01](../bibliography/01-datasheets.md) #23, [06](../bibliography/06-reference-projects.md) #50); failing that, amend this ADR with a named vendor-blob exception; failing that, drop the feature engine and compute wrist-raise from raw ±2 g / 50 Hz samples ([ADR 0012](0012-hands-free-interaction.md)).
- **Decision history — recorded because it was reversed twice in one day:**
  - The project was first going to be **GPL-3.0** outright, by default and by imitation of the tools it studies (Friture, Praat, the ESP32 analyzer prior art).
  - It was then set to **Apache-2.0** for the whole repository, on the argument that the firmware's value is in being reusable and upstreamable.
  - On **2026-08-20** the owner asked whether GPL would in fact be *more* compatible, given that so much of the surrounding ecosystem is GPL. The answer that produced this ADR: it is more compatible for exactly one thing — the host's in-process parselmouth import — and for nothing on the watch, because compatibility is one-way ([03](../bibliography/03-standards.md) #39). A GPLv3 repository would still not let GPL code onto the firmware link line in a way anyone could reuse, and it would close off upstreaming to ESP-IDF and Zephyr, both Apache-2.0. Splitting at the one directory that needs GPL costs nothing and buys both. The split shipped in the initial commit and is stated in [`NOTICE`](../../NOTICE) and [`README.md`](../../README.md#license).
  - On **2026-08-20/21** the D3 acquisition pass filed 44 PDFs and a blanket `git add docs` swept all of them into the tree. The 33 classified `no`/`unknown` were removed from the index that night and the **history was rewritten on 2026-08-21** to purge the blobs themselves (the purged list survives as `scratch/d3-purged-paths.txt`, gitignored; `.git/info/exclude` now carries the same paths). Cheap only because the repository was hours old, had one contributor and no forks; the rewrite was force-pushed with `--force-with-lease` and a pre-rewrite bundle was kept. On any repository with other clones this option does not exist, which is the real argument for item 8. That incident is why item 8 is part of this ADR rather than a paragraph in a README.
- **Alternatives:**
  - *GPL-3.0-or-later for the whole repository.* Rejected 2026-08-20: it buys the firmware nothing (one-way compatibility), forfeits upstreaming to ESP-IDF/Zephyr and reuse by permissive embedded projects, and would make every managed component's licence a question. **Revisit trigger:** the project abandons upstreaming *and* a GPL embedded component becomes load-bearing on the watch — neither is in sight.
  - *Apache-2.0 for the whole repository, `host/` included.* Rejected: parselmouth imports Praat in the same process; there is no reading of GPLv3 §5 under which that combined work ships permissively, and nobody can sublicense Praat.
  - *Keep `host/` Apache-2.0 and call Praat out-of-process* (`praat --run` scripts, parse the output). Rejected: the arm's-length argument is defensible for fork/exec but the golden-file generator wants the parselmouth API and its **bundled** Praat pinned by version and method ([ADR 0009](0009-golden-file-strategy.md), [`golden-files.md`](../validation/golden-files.md)); trading that for a licence convenience would weaken the strongest external anchor the project has. **Revisit trigger:** a downstream permissive project needs the offline analysis — then the CLI route is the migration path.
  - *MIT or BSD-3-Clause instead of Apache-2.0 for the default.* Rejected: no express patent grant and no `NOTICE` mechanism, and ESP-IDF itself is Apache-2.0 — matching it is what makes an upstream PR a formality.
  - *Dynamically link the LGPL pieces (arduino-esp32) and satisfy §6a that way.* Rejected: ESP-IDF applications are statically linked monoliths; there is no dynamic-link story on this target, and §6a's object-code-plus-relink route is a poor fit for an OTA image on a sealed watch.
  - *Commit the whole reference library and rely on research/fair use.* Rejected: a public Apache-2.0 repository *redistributes*; unstated vendor terms would make the repository unsafe to fork, which is precisely the property the licence choice exists to protect. The manifest row plus `_notes.md` keeps the citation chain without the bytes.
- **Consequences:**
  - (+) The firmware is genuinely reusable: a third party can fork it under Apache-2.0 obligations only (`NOTICE` + SPDX), and the PDM/FFT work stays upstreamable to two Apache-2.0 projects.
  - (+) The boundary is auditable in seconds — one directory, one `LICENSE`, one SPDX string, plus `esp-idf-sbom` output on every PR — instead of living in a reviewer's memory.
  - (+) The exclusion decisions are recorded *with their targets named* ([06](../bibliography/06-reference-projects.md)), so a future session cannot re-discover arduinoFFT or `esp32-fft` as a shortcut.
  - (−) Anything needed on both sides is implemented twice — once in Apache-2.0 `spectral_core`/`python-scripts/`, once under GPL `host/` — or driven through files. This is a permanent tax on the watch↔host agreement work, and a source of divergence the golden-file tolerances have to catch.
  - (−) The rule forbids the fastest path repeatedly: arduinoFFT, the m5Cardputer UI, ikostoski's A-weighting IIR, the Arduino pin header. Re-deriving each from the standard or the paper costs hours and adds bugs the original had already fixed.
  - (−) `host/` is a standing exception to the Python-location rule and has to be re-explained in every onboarding document; exceptions of this shape grow if unwatched.
  - (−) GPL-3.0-or-later makes `host/` unattractive to a commercial downstream user, who gets the firmware and the protocols and must write their own offline analysis. Deliberate, but it is a real cost to the "companion" story.
  - (−) The repository alone does not reproduce the bibliography: of the 46 filed documents only 12 are `redistributable=yes`; the rest exist as a sha256 row and a link, and a fresh clone must re-fetch them from [`acquisition-status.md`](../bibliography/acquisition-status.md) against link rot we do not control.
  - (−) Nothing enforces item 8 mechanically. The SPDX/REUSE hooks cover source files, not the library, and writing this ADR found one counter-example already in the index — `docs/reports/nti-audio/nti-audio_xl2-manual_fw4.93_2026.pdf` (11.2 MB, `redistributable=unknown`), committed on 2026-08-21 although the ledger records it as local-only. Until a CI check greps tracked PDFs against column 11 of the manifest, this rule is enforced by review, and review missed it once already.
  - (−) A second history rewrite would be far more expensive: after the repository is published, the same mistake means a force-push plus copies in every fork and cache. The window in which item 8 is cheap to enforce closes when the remote is created.
  - (−) The policy is not currently clean: item 9's Bosch feature-blob files ship in every OTA image without a redistribution grant, and `NOTICE` describes them wrongly until that is resolved. An ADR that claims a strict link-line rule while carrying an unresolved exception is only useful if the exception stays visible.
  - (−) The licence of a dependency can change under us (LVGL and SensorLib are the load-bearing MIT ones); the `NOTICE` rows and the SBOM check must be read on every version bump, not just on first addition.

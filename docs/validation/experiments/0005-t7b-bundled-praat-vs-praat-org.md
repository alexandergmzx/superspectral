# Golden files: bundled Praat 6.1.38 vs praat.org 7.0.01 (threshold T7b)

**Date:** 2026-08-22 (pre-registered) · **Status:** planned — owner Alexander (needs a praat.org binary run out of process; nothing in this recipe runs on the watch).

The golden files ([ADR 0009](../../adr/0009-golden-file-strategy.md)) are generated by `praat-parselmouth==0.4.7`, which bundles **Praat 6.1.38** (2021-01-02) and registers only the raw autocorrelation pitch method (T7a, closed by measurement 2026-08-21 — [roadmap](../../roadmap/documentation-roadmap.md) threshold table). praat.org ships **7.0.01** (`PRAAT_VERSION_STR 7.0.01`, 2026-08-18, `main/main_Praat.h` of the pinned clone — [06 #31](../../bibliography/06-reference-projects.md)), whose default pitch method has been *filtered* autocorrelation since 6.4 (2023-11-15). The research question's "≤ 5 cents vs Praat" therefore currently means *Praat 6.1.38, raw autocorrelation*. T7b asks whether that qualifier costs anything: does the same WAV give the same numbers out of the bundled and the current binary when the **method is held fixed** (version drift), and how far does the **default method** move them (method drift)? The two drifts are measured separately and never summed.

## What changed / hypothesis

No firmware and no golden set changes. One tier-0 WAV and one vowel WAV go through three pitch extractions and two formant/LTAS extractions:

| Arm | Engine | Pitch method | Role |
|---|---|---|---|
| **A (baseline)** | parselmouth 0.4.7 → Praat 6.1.38, in-process | `To Pitch (ac)` with the golden set's eleven parameters | what the golden files already contain |
| **B** | praat.org 7.0.01, out of process, `--run` | `To Pitch (raw autocorrelation)` — same eleven parameters | **version drift**: same algorithm, five years of code |
| **C** | praat.org 7.0.01, out of process, `--run` | `To Pitch (filtered autocorrelation)` with Praat's defaults — floor 50 Hz, top 800 Hz, attenuation at top 0.03, silence 0.09, voicing 0.50, octave cost 0.055, octave-jump 0.35, voiced/unvoiced 0.14 (read from `fon/praat_Sound.cpp` `Sound_to_Pitch_filteredAutocorrelation` FORM of the pinned clone `f38ba40b`; the raw form's defaults there are 75/600 Hz, 0.03/0.45/0.01/0.35/0.14) | **method drift**: what a 2026 Praat user gets by default |

**Hypothesis H1 (version drift is below the tolerance):** median |Δcents| between A and B over voiced frames ≤ 1 cent on the sine and ≤ 2 cents on the vowel; the voiced/unvoiced decision agrees on ≥ 99 % of frames; formant F1–F3 (Burg, same parameters) agree within 1 Hz; LTAS band levels agree within 0.01 dB. If H1 holds, the "vs Praat 6.1.38" qualifier is a bookkeeping fact, not a scientific one.

**Hypothesis H2 (method drift is measurable but bounded):** median |Δcents| between A and C ≤ 5 cents on the vowel's steady portion; onset/offset frames differ by whole frames (expected — the filtered method's silence and voicing thresholds are different numbers, ADR 0009 amendment); the difference is *reported*, not folded into any tolerance.

Run command (host, GPL environment; the `t7` subcommand is roadmap H0 unit B-U10 — until it lands, the manual steps below are the recipe):

```sh
# 1. praat.org binary, pinned by sha256 — record both in Provenance
PRAAT=~/opt/praat/praat_7.0.01            # barren/no-GUI build for Linux, from praat.org/download_linux.html
$PRAAT --version                          # must print 7.0.01
# 2. arms B and C: Praat 7.0 refuses to save files from a script unless the caller grants trust
#    (sys/praat.cpp: `--FULL-TRUST  allow this script to save files and run system commands`);
#    the script writes the .Pitch/.Formant/.Ltas results as short text files, so the flag is required.
$PRAAT --run --no-pref-files --FULL-TRUST host/golden/t7/praat_t7b.praat \
       datasets/tier0-synthetic/vowel_a_f0_220_32k.wav  build/t7b/
# 3. arm A and the comparison (in-process, parselmouth)
uv run --project host spectral-golden t7 --praat "$PRAAT" \
       --input datasets/tier0-synthetic/vowel_a_f0_220_32k.wav --out build/t7b/
```

The Praat script reads one WAV, runs the three extractions, and writes `*.txt` short-text objects plus a `versions.txt` (`praatVersion$`, `praatVersion`); it takes its parameters on the command line so that the eleven raw-ac numbers are copied from the golden manifest, never retyped.

## Scope caveat

Two binaries on one x86-64 host, double precision on both sides: this experiment sees Praat's own algorithmic evolution and nothing else. It cannot see the Xtensa-vs-x86 libm trap, the float32 accumulation trap or the frame-grid trap ([`golden-files.md`](../golden-files.md) §Gotchas) — those belong to the device-vs-host comparisons. It also cannot rank the two methods: a synthetic vowel has a known f0, so the arm closer to the ground truth is the *more accurate* one on this material, which is not the same as "better on singing".

## Hypothesis / Setup / Pass–fail

- **Setup:** tier-0 WAVs regenerated and `check`-clean; golden set `tier0-synthetic` verified green (`spectral-golden verify`); praat.org binary pinned by sha256; the Praat script run once with `--FULL-TRUST` and its outputs inspected by eye (a `.Pitch` short-text file with the expected frame count `nx`, `dx` = 0.01 s, `x1` per Praat's centring rule).
- **Pass H1:** A-vs-B median |Δcents| ≤ 1 (sine) / ≤ 2 (vowel) over frames voiced in both; V/UV agreement ≥ 99 %; F1–F3 within 1 Hz; LTAS bands within 0.01 dB. Any residual is reported with its maximum and the frame index where it occurs.
- **Pass H2:** A-vs-C median |Δcents| ≤ 5 on the vowel's steady portion (0.5 s – 2.5 s); onset/offset disagreements counted and listed, not averaged away.
- **Fail H1:** the "≤ 5 cents vs Praat" qualifier is scientific, not bookkeeping → the proposal wording names the version *and* the residual; the golden-files table gains a row "bundled vs praat.org, raw-ac" with the measured number and this experiment as its anchor; no tolerance is widened without a recorded reason (golden-files.md rule).
- **Fail H2 (> 5 cents):** the RQ target is method-dependent on synthetic material → ADR 0009 amendment stating which method the RQ means, and a second golden set `tier0-synthetic-filtered` becomes a named Phase-1 deliverable (schema "1.2", pitch top + attenuation).
- **Repetitions:** ×1 per arm is sufficient (both engines are deterministic on one host); re-run once after any parselmouth or praat.org pin change, and the result appended below, never overwritten.

## Gotchas (pre-registered)

- **`--FULL-TRUST` trap.** Praat ≥ 7.0 runs a script from the command line *untrusted* unless `--FULL-TRUST` is given; an untrusted script that reaches `Save as short text file:` stops with an error, and a script that only `writeInfoLine`s looks like it worked. *Signature:* arms B/C produce `versions.txt` and nothing else. *Pin:* the run command above; the `t7` subcommand passes the flag itself and fails if the expected output files are absent.
- **Raw-vs-default trap.** `To Pitch (ac)` in 6.1.38 and `To Pitch (raw autocorrelation)` in 7.0 are the same algorithm under two names (7.0.01 registers `To Pitch (raw autocorrelation)... || To Pitch (raw ac)...` and keeps `To Pitch (ac)...` as a hidden alias — `fon/praat_Sound.cpp`); `To Pitch...` (no qualifier) in 7.0 is the *filtered* method. *Signature:* arm B silently becomes arm C and H1 "fails" by exactly the H2 amount. *Pin:* the script names the method in full and asserts `praatVersion >= 6400` before using the new names.
- **Centring trap.** Praat's first frame is at `t1 = (duration − (nFrames − 1)·dt)/2`; parselmouth exposes the same `xs()`. Compare by time, never by index, and only on frames voiced in both arms.

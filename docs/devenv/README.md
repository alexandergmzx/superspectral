# Development environment

The reproducible ESP-IDF environment for Super Spectral: what is pinned, how to install it, how to upgrade it, and how to get a sealed watch back when it stops talking. Everything here answers the project's stated worry — *"may cause a lot of troubles later if not done correctly"* — by making the environment two committed lines ([`.envrc`](../../.envrc)) plus one inventory ([env.lock.md](env.lock.md)), and by writing the recovery procedures **before** the first flash.

**The pin (verified 2026-08-20):** ESP-IDF **v6.0.2** (Service to 2027-03-20, EOL 2028-09-20 — the longest runway of any shipped line; v5.5 EOLs eight months earlier despite being older), manual full clone at `~/esp/idf/v6.0.2`, private tools root `~/esp/tools/v6.0.2`, Python `/usr/bin/python3.12`, activation only via direnv. Rationale: [ADR 0001](../adr/0001-toolchain-esp-idf-v6-pinned-environment.md) (proposed; accepted after the E1 gate build). Evidence: bibliography [11](../bibliography/11-esp-idf-platform-and-toolchain.md).

## Three rules that never bend

1. **Never touch GPIO19/GPIO20** (USB-Serial-JTAG D−/D+) — `_Static_assert` in `twatch_bsp/include/twatch_pins.h` + the `no-usb-pins` pre-commit hook. The board has zero exposed GPIO and BOOT is inside the case; USJ is the only recovery path.
2. **Never burn eFuses** — `espefuse` is read-only for the life of the project (`summary`, `dump`). Secure Boot and Flash Encryption stay `=n`, asserted by pre-commit. `set-flash-voltage` would destroy the 1.8 V W25Q128JW.
3. **Never flash `ota_0` by hand** — it holds the golden recovery image. Development builds go to `ota_1` through [`tools/flash.sh`](../../tools/flash.sh), which also arms rollback (`ESP_OTA_IMG_NEW`) so an image that never reports healthy is reverted by the bootloader.

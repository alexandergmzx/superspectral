# 02 — Application notes, programme documentation and API references

Where vendors document what the datasheet leaves out: driver contracts, configuration rules, measured performance ladders, mounting guidance. Read the relevant section *before* writing the corresponding driver, `sdkconfig` block, or bench procedure. Entries are grouped by subsystem in bring-up order ([roadmap](../roadmap/documentation-roadmap.md) E0 → E2 → firmware M0): platform and build, audio capture, DSP, display, memory/power/tasks, recovery, testing and CI, board-support references, then the **MEMS-microphone acoustics** notes that bound the in-situ measurement.

Priority key: ★★★ must-have/blocking · ★★ strongly recommended · ★ useful background (defined in [README](README.md)). ADR numbers refer to [`../adr/README.md`](../adr/README.md); "§n" refers to the [proposal](../proposal/01-super-spectral-proposal.md); metric names are rows of the [validation plan](../validation/README.md); component names are directories under [`firmware/twatch-s3/components/`](../../firmware/twatch-s3/README.md).

**Two conventions specific to this file.**

1. **Espressif programme documentation drifts.** Pages under `docs.espressif.com/projects/esp-idf/en/stable/…` follow whatever `stable` is this month. Every ESP-IDF entry below is acquired as a **dated PDF snapshot of the v6.0.2 rendering** (`…/en/v6.0.2/esp32s3/…`, the version pinned by [ADR 0001](../adr/0001-toolchain-esp-idf-v6-pinned-environment.md)), filed under [`../app-notes/espressif/`](../app-notes/README.md), and re-snapshotted only by the [upgrade procedure](../devenv/upgrade-procedure.md). Component READMEs and headers are snapshotted at the tag named in the pin (`espressif/esp-dsp` 1.8.2, `esp_lvgl_port` 2.9.0, `esp_lcd_touch_ft5x06` 1.1.1, `lewisxhe/sensorlib` 0.4.1).
2. **This file is the home address for the thematic file [11](11-esp-idf-platform-and-toolchain.md).** 11 lists the same Espressif documents under local numbers `A1…A39`, sectioned by the *claim* each grounds; this file is the by-type index that owns the entry number and the acquisition link. The cross-map is at the end ([Home addresses for 11](#home-addresses-for-the-local-numbers-in-11)).

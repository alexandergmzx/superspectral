# 11 — ESP-IDF platform and toolchain ("the environment will not bite us later")

**Purpose.** Every other thematic file defends a *measurement* claim. This one defends an *engineering* claim the user made explicit: that the development environment, pinned once in phase E0/E1, will not cost weeks later through version drift, a silently half-configured PSRAM, a bricked sealed watch, or a burned eFuse. The environment decisions in [ADR 0001](../adr/0001-toolchain-esp-idf-v6-pinned-environment.md), [0014](../adr/README.md), [0015](../adr/README.md), [0016](../adr/README.md), [0017](../adr/README.md) and [0019](../adr/README.md), and every procedure under [`docs/devenv/`](../devenv/README.md), cite the documents listed here. This is the reading list that turns "we pinned v6.0.2" into "we pinned v6.0.2 *because*".

This is a **thematic list** (01–07 are organised by document *type*): sections follow the *claim each document grounds*. Most entries are Espressif programme documentation that tracks the `stable` branch and **drifts** — they are acquired as **dated PDF snapshots** of the v6.0.2 rendering (the URL form `…/en/v6.0.2/esp32s3/…` is preferred over `…/en/stable/…` when the snapshot is taken), filed under [`../app-notes/espressif/`](../app-notes/README.md) and extracted with `doc_ocr` like everything else.

**How this file numbers things.** A row whose `#` is an address like `07 #16` is already indexed in a by-type file — that entry is authoritative and carries the acquisition link; it is repeated here so the claim→evidence map is complete. Rows with a *local* letter-prefixed number are listed here first because their by-type home was authored in parallel: `A1…` app notes / programme docs (home [02](02-application-notes.md)), `R1…` reports and living pages (home [07](07-technical-reports.md)), `P1…` projects and tool repositories (home [06](06-reference-projects.md)). They receive their home address when the indexes freeze (roadmap D3). Local numbers are append-only. Cite as `11 A7`.

## A. The version, its support window and the sanctioned install path — why v6.0.2, and why a manual clone

Grounds ADR 0001's pin, its install clause (full recursive clone + private `IDF_TOOLS_PATH` + direnv; EIM and the VS Code installer rejected), [setup.md](../devenv/setup.md) §1–§5 and the [upgrade procedure](../devenv/upgrade-procedure.md)'s triggers. The counter-intuitive fact that decides the choice: ESP-IDF has no LTS line; every minor gets a flat 30 months (12 Service + 18 Maintenance) from its own GA, so **v5.5 (EOL 2028-01-21) expires eight months before v6.0 (EOL 2028-09-20)** despite being older. v6.0 is the only line in Service on 2026-08-20.

## B. The go/no-go gate — the one experiment that can invalidate the pin

Grounds [setup.md §6](../devenv/setup.md) and ADR 0001's "gate build required" clause. Neither `esp-dsp` (`idf >=4.2`) nor `esp_lvgl_port` (`idf >=5.2`) nor `esp_lcd_touch_ft5x06` (`idf >=5.2`) declares an *upper* IDF bound, so none of them promises v6.0 compatibility; v6.0's warnings-as-errors + gnu23 is the classic breakage point ([pitfalls B11](../devenv/pitfalls.md)). The gate resolves this empirically in 30 minutes.

# 06 — Reference open-source projects

Other people have already built most of the pieces: PDM capture on this silicon, FFT→spectrogram on a small SPI TFT, the board's own drivers, the host-side evaluation stack. Read their code, take their good ideas, learn from their failures — and **check the licence before a single line is copied**.

**Licence policy (ADR 0004 — split licensing, pre-registered in the [ADR backlog](../adr/README.md) as `0004-split-licensing.md`; stated in the root [`NOTICE`](../../NOTICE)).** Firmware, tooling and docs are Apache-2.0; only the [`host/`](../../host/README.md) tree is GPL-3.0-or-later. The **License** and **Apache-2.0-compatible?** columns are therefore mandatory and are evaluated for the *firmware link line*:

| Upstream licence | Apache-2.0-compatible? | What that means here |
|---|---|---|
| MIT · BSD-2/3 · Apache-2.0 · CC0-1.0 · ISC | **yes** | May be linked, vendored or adapted; keep the copyright line in `NOTICE`, SPDX header on every file touched. |
| LGPL-2.1 (`arduino-esp32`) | **avoid (static link)** | §6 relink obligation on a statically linked firmware image, plus forced Wi-Fi stack and IDF-version anchoring. Read-only; never open `variants/` while writing the board file. |
| GPL-2.0 / GPL-3.0 / AGPL-3.0 | **read-only** | Study algorithms and UI ideas; reimplement from the cited paper, never from the code. GPL tools may be *run* on the host and GPL libraries may be *imported* under `host/` only. |
| "Espressif MIT" (ESP-ADF, ESP-SR) | **no — field-of-use** | "for use on all ESPRESSIF SYSTEMS products" is not OSI MIT; derivatives are not portable open source. Excluded from the firmware; usable as a yardstick document only. |
| No licence field · NOASSERTION | **read-only** | All rights reserved by default. Inventory only. |

Priority glyphs (★★★ / ★★ / ★) open each **What to take** cell. Entry numbers are append-only; cite as `06 #<n>`. Local landing zone and clone policy: [`../reference-projects/README.md`](../reference-projects/README.md) (catalogue here, clone on demand into gitignored `clones/`).

## How to use this list

For each firmware component about to be written, pick the one or two projects above whose code most closely overlaps (the clone-first shortlist in [`../reference-projects/README.md`](../reference-projects/README.md) is that mapping). Spend an afternoon reading the implementation and its issue tracker. Write the takeaways — what they do well, what they avoid, which gotchas they hit — into `clones/<project>_notes.md` and then into an ADR under [`../adr/`](../adr/README.md) **before** writing our version. The first such ADR (0018) covers #3, #4 and #7. Swarm specified this loop and never closed it; roadmap phase D4 makes closing it a definition-of-done item.

# 07 — Technical reports, vendor pages and grey literature

Grey literature: vendor product pages, wiki and board-documentation snapshots, commercial-analyzer manuals, evaluation-campaign pages, platform support policies, and the one **artifact** (a vendor firmware binary) the project flashes once. Most are free; almost none are indexed by Google Scholar; several are *living web pages* that change without versioning — which is why they are captured as dated PDF snapshots rather than bookmarked.

Sections follow the agency directories of [`../reports/`](../reports/README.md). Entry numbers are append-only; cite as `07 #<n>`. § numbers refer to the [proposal](../proposal/01-super-spectral-proposal.md); ADR numbers to the [ADR index](../adr/README.md); roadmap phases to the [documentation roadmap](../roadmap/documentation-roadmap.md). Priority: ★★★ must-have/blocking · ★★ strongly recommended · ★ useful background.

**Snapshot rule for living pages:** print-to-PDF the page *and* run `python3 -m doc_ocr extract` on it ([`../OCR/README.md`](../OCR/README.md)); name the file with the full capture date (`<agency>_<short-title>_YYYY-MM-DD.pdf`) because the page will drift. The ESP-IDF programme documentation itself (build system, drivers, Kconfig, migration guides) is indexed in [02](02-application-notes.md) and [11](11-esp-idf-platform-and-toolchain.md), not here.
